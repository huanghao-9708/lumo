## DM-05 数据窗口与返回上下文（本次提交）——已完成

### 实现

1. **释放/恢复事务**（验收 1/3，player.ts）：
   - `watch(windowForm)`：进入迷你 → `snapshotBrowseContext()`（tab/详情 id/搜索词/歌曲锚点偏移与 id）+ `releaseBrowseData()`（tracks/albums/artists/favorite*/playlists(含 base64)/smartPlaylist/三个详情/文件夹/艺人 LRU/可播性/insights/stats/歌词全部清空，**queue/index/进度等核心会话不动**）；
   - 返回完整 → `pendingBrowseRestore`，由 MainContent `onMounted` 消费 `applyBrowseRestore()`：id 归 null 再落位（强制详情 watcher 重载）+ `seedTracksWindow(锚点偏移)` **整体替换为 200 行窗口**——不从第一页逐页回放；
   - 播种带 generation 自增，在途 append 响应作废；后续 fetchTracks 从窗口末端续接。
2. **scan-complete 条件化**（验收 2）：非视觉态（极简/迷你）扫描完成只 `fetchCounts` + 来源表刷新 + `browseDirty` 标记；恢复视觉态上升沿**合并刷新一次**（pendingBrowseRestore 存在时让位——恢复路径本身即取到扫描后最新数据，dirty 一并清除）。
3. **筛选后全选 = 完整结果集**（验收 4）：
   - 后端新增 `TrackRepo::get_track_ids`（与分页查询同一 WHERE/ORDER 的 ids-only 查询）+ 命令 `library_get_track_ids`；
   - `useBatchSelect` 增加 `selectAllIds`/`resultWide`（结果集级全选语义），批量动作照旧消费 ID 集合；
   - MainContent：有筛选词时全选拉完整 ID 集（低频显式动作）；失败回退已加载窗口并提示（验收 5 的可理解回退）。
4. **旧响应防护**（验收 5）：既有 reqId/generation 守卫 + 播种 generation；锚点行不在恢复窗口内时列表仍可用（默认视图）。

### 设计偏差

- 专辑/艺人网格的恢复目前为第 1 页重取（歌曲列表为锚点窗口）——网格最深分页场景显著浅于歌曲列表（30/页 vs 50/页），M3 按实测扩展窗口播种。
- 无筛选时的全选保持「已加载窗口」语义（仅筛选后升级为结果集级）——避免无差别全库选中的危险默认。
- `get_track_ids` 无独立 Rust 测试（SQL 与分页查询同源镜像），前端流程测试覆盖；M4 补仓库层测试。
