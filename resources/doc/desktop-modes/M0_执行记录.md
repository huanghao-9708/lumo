## 窗口 API 探针结论

探针实现：`src/dev/windowProbe.ts`（临时，`LUMO_WINDOW_PROBE=1` 布防、启动 3s 后自动执行；结果经 stderr `[WINDOW_PROBE]` 输出 + 屏幕覆盖层；clamp 决策经 `probeLog` 同通道追踪）。命令 `dev_window_probe_signal`/`dev_window_probe_log` 在 `src-tauri/src/commands/debug.rs`（延续 MA0 Spike 模式，debug 构建编译）。**DM-07 落地后连同本文件记录一起移除。**

原始输出（两次运行，第二次含隔离实验与插桩）：

```text
[INFO] 初始状态 — 尺寸 1200×720，最大化=false，工作区 1707×1067@1.5
[INFO] 多显示器枚举 — 1 台：1707×1067@1.5
[PASS] 隔离：纯净最大化→还原 — +50ms:max=true,1707×1066 +250ms:max=true +500ms:max=true；还原后 1200×720
[PASS] 解除约束→560×96 — 实测 560×96，minWidth=1024 解除后未被拉回
[SEAM] 迷你宽度 vs <768 断点 — innerWidth=560，落入 MobileLayout 断点
[PASS] 迷你下恢复约束 — 实测 560×96，约束未即时改写窗口
[PASS] 恢复 1200×720 — 实测 1200×720
[clamp] setSize 1707×1067（当前 1707×1073）
[FAIL] 最大化→还原 — +50ms:max=false,1707×1073 +250ms:max=false,1707×1067 …；unmaximize 后 1707×1067
[PASS] 置顶开→关 — isAlwaysOnTop 开=true 关=false
[PASS] 恢复现场 — 约束=1024×640，尺寸 1200×720，置顶=关，播放未触碰
```

验收 2/3 达成：迷你 560×96 在解除约束后稳定保持、探针任一步失败后恢复现场（约束/尺寸/置顶全部还原）、全程未触碰播放（音频未重启）。验收 2 的两个候选接缝实测结果：

1. **原窗口限幅拉回：不成立（PASS）**——解除约束后 560×96 保持；在迷你尺寸下恢复 1024×640 约束也**不会**即时拉大窗口（实测推翻了按 tao `set_inner_size_constraints → set_inner_size(current)` 代码推导的「会被拉回」假设）。
2. **`<768` 移动断点：成立（SEAM）**——560 宽必然落入现有 MobileLayout 断点，DM-06 必须实现「桌面迷你优先于宽度断点」的判定分离（计划 §5 已有此项）。

**新发现接缝（DM-07 设计输入，本次最重要的结论）**：

- **纯净路径**：无前置操作时 `maximize()` 后 `isMaximized()` 稳定 true（+50/250/500ms 三点采样），还原正确 → 用户按钮流（e594cd2 修复）与隔离实验均通过。
- **污染路径**：经过 `setSizeConstraints(null) → setSize(迷你) → setSizeConstraints(1024×640) → setSize(完整) → center()` 序列后，紧接着的 `maximize()` 出现 **tao 缓存标志与真实窗口状态脱钩**：几何到达最大化尺寸（1707×1073，带边框悬出），但 `isMaximized()` 自 +50ms 起为 false；随后持久化 clamp 的守卫读到 false 放行，`setSize(1707×1067)` 把最大化状态破坏为「工作区尺寸的普通窗口」。机制对应 tao `apply_diff` 中 `SW_MAXIMIZE` 与 `SetWindowLongW` 风格重写/`MARKER_RETAIN_STATE_ON_SIZE` 的竞态（WM_SIZE 的 SIZE_MAXIMIZED 同步被 marker 窗口吞掉）。
- **对 DM-07 的三条硬约束**：① 转换事务**不得信任 `isMaximized()` 瞬时读数**，必须自行跟踪「完整窗口最大化」状态（进入迷你前记录、返回时以记录值为准）；② 几何转换窗口期必须**整体冻结持久化 clamp**（transition lock，计划已有，本次实证其必要性）；③ 纯净路径已验证可用，正常用户流程不受影响。

## 设计假设修订（退出前必答）

1. **GPU 进程主导成立**：gpu ≈54% 整组且静置不释放。DM-03 的收益上限 = renderer + utility + 网络，gpu 收益只能来自 DM-04 关闭模糊/光晕/动画（合成输入减少）。建议 M1 的 DM-03 把「合成层预算」纳入极简 token 清单，M4 用「同几何关闭图片 vs 关闭装饰」两轮实验拆分归因。
2. **约束拉回假设被推翻**：恢复 min constraints 不会即时拉大小窗口 → DM-07 转换顺序约束放宽，但仍需处理「迷你期间用户手拉窗口越过完整最小尺寸」的边角（原生约束在迷你态应保持迷你约束，DM-07 按形态切换约束即可）。
3. **isMaximized 脱钩假设新增**（原计划未预见）：DM-01/DM-07 的状态机必须自带最大化状态权威，见上节三条硬约束。
4. 其余「迷你几何 API」步骤全部可用（setSize 逻辑像素跨 150% DPI 正确、置顶可编程开关、显示器枚举可编程读取）；物理换屏/拔屏/DPI 热切换仍需实机人工项（W03/W05）。
