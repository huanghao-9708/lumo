# 产品交互与技术设计

> 日期：2026-09-30 · 状态：实施设计，所有新增能力均待实现  
> 返回：[总计划](README.md)

## 1. 两个维度与四种组合

| 体验模式 | 完整窗口 | 迷你播放栏 |
|---|---|---|
| 正常 | 保留现有视觉，图片按需加载，所有缓存有界 | 仅文字与必要操作，不显示封面；返回后恢复正常体验 |
| 极简 | 搜索、紧凑列表、文字详情和文字播放页；不加载界面图片 | 同一轻量播放栏；返回后恢复极简体验 |

日夜主题为独立设置。正常+迷你与极简+迷你的栏内视觉及资源策略一致，差别在返回完整窗口后的体验；不能在迷你中暗中保留正常界面。最小化仍是操作系统窗口状态，不等于迷你形态。

新用户默认正常+完整。记住上次成功提交的体验与形态，支持直接以迷你冷启动；新偏好不能引入自动播放行为。回退或损坏配置默认正常+完整，后台可选视觉任务在配置确认前保持关闭。

## 2. 入口与完整窗口

- `TopBar` 日夜按钮旁新增有文字提示的“体验模式”菜单：正常模式、极简模式；标明选中项，键盘可打开/选择/关闭，焦点回到触发按钮。
- 同组新增“进入迷你播放栏”按钮，和体验菜单分别操作；菜单不把四个组合混成互斥的四种模式。
- 正常沿用当前完整布局。极简首页用搜索、最近播放与歌曲入口；专辑/艺人改文字列表，详情不展示封面；复用现有歌曲列、选中态和批量操作。
- 极简保留字号与点击目标，不能用整体缩放降低可读性。使用实色背景，关闭背景模糊、光晕、装饰阴影、呼吸/抽屉等非必要动画；保留选中、禁用、加载、错误和焦点反馈。
- 极简文字播放页保留控制与歌词入口；歌词在显式打开时加载，沿用既有联网授权。关闭后释放解析/滚动状态，切歌时仅在可见时刷新。
- 切体验模式保持当前曲目、进度、音量、队列、排序/筛选和当前页面。关闭旧沉浸视觉；若正在查看歌词，转换到文字播放页，不恢复过时视觉任务。
- 模式切换不改用户的封面/歌词联网偏好，极简只是暂停视觉需求。返回正常也仅在既有授权及页面需求同时满足时联网。

## 3. 迷你播放栏

### 3.1 结构

```text
┌─────────────────────────────────────────────────────────────────┐
│ 歌名 · 歌手       上一首  播放/暂停  下一首   音量  返回  更多 │
│ 00:42 ───────────────────────进度────────────────────── 03:25 │
└─────────────────────────────────────────────────────────────────┘
```

尺寸为 560×96 逻辑像素，最小 480×96，建议允许水平调整至 800；具体值在 M0/M3 的 DPI 样本中校准。避免高度自由调整导致只剩空白。按钮目标至少 32×32，正文基准约 13px。

- 不展示封面、光谱、波形、动画背景、自动跑马灯或常驻曲库。
- 长歌名省略，悬停或键盘聚焦可看完整文本。状态区域显示缓冲/错误；用户能暂停、重试或返回完整界面处理，不能只有转圈。
- Seek 拖动只更新本地预览，释放时一次提交；沿用音量和播放语义，不新增解码链路。
- 更多菜单：正常/极简、播放顺序、置顶开关、最小化、退出。置顶初始关闭，仅迷你有效；完整形态始终关闭该置顶状态。
- 迷你不增加队列/歌词常驻面板，浏览或编辑操作返回完整窗口；空队列显示“尚未选择歌曲”与返回入口，不自动扫描或播放。
- 提供明确拖动区域；按钮、进度条和菜单不属于拖动区域。任务栏入口保留，关闭/退出沿用现有退出语义，不新增隐藏到托盘的行为。
- 按钮保留中文名称、焦点和屏幕阅读标签；保留现有播放快捷键，range/input/menu 聚焦时快捷键不得吞掉其原生操作。

### 3.2 浏览恢复

保存轻量上下文：页面类型、实体 ID、搜索词、筛选/排序、锚点歌曲/专辑 ID、锚点偏移、左右面板偏好和焦点来源。多选以 ID/选择表达式保存，数据更新后重校验；迷你不允许执行批量操作。

完整数据数组、详情图片、歌词解析和 DOM 不随上下文保留。返回时以锚点附近的数据窗口恢复，不从第一页逐页拉取到原位置。被删除的实体回到对应上级列表并提示；搜索结果变化允许恢复到最近可用锚点。恢复流式加载，避免无界“还原整页”。

备份恢复、标签写入、未保存编辑等不可中断或可能丢失输入的对话框打开时，入口暂不可用并说明原因；关闭或完成后可切换。普通用户主动扫描/传输可继续，迷你只保留摘要/失败通知，不因切换取消或重新执行。

## 4. 状态与转换事务

建议由单一桌面模式控制器负责，不把状态散落在各组件：

```ts
type ExperienceMode = 'normal' | 'minimal';
type WindowForm = 'full' | 'mini';
type TransitionPhase = 'idle' | 'entering-mini' | 'leaving-mini' | 'changing-experience';
// 偏好包含 schemaVersion、experienceMode、windowForm、两套 geometry、miniAlwaysOnTop。
// 运行态另含 transitionId、phase、浏览上下文和资源策略；失败不写成成功偏好。
```

每次转换串行执行；转换中禁用重复点击，旧异步结果通过 transitionId/策略版本丢弃。用户仍能播放/暂停和关闭窗口，不能让 UI 等待网络完成。

### 4.1 完整 → 迷你

1. 验证当前无阻止切换的编辑/恢复；保存完整窗口位置、尺寸、最大化状态及轻量浏览上下文，冻结窗口状态自动保存。
2. 先关闭视觉需求和新增浏览加载；取消可取消任务，标记旧响应过期；待已有数据库写事务安全结束后暂停可选图片后台任务。
3. 卸载完整浏览工作区、Inspector、沉浸页和浏览弹窗；释放浏览数组、图片与视图监听。常驻会话控制层不卸载。
4. 按 API 探针结果依序退出最大化、放宽完整最小尺寸、应用迷你几何/工作区限幅及置顶偏好；迷你挂载优先于 `<768` 布局断点。
5. 成功后提交形态/偏好，切换为迷你几何的保存规则。窗口失败则恢复完整约束、几何与资源策略；数据可重新查询，播放保持。

### 4.2 迷你 → 完整

1. 暂停迷你几何保存与视觉需求，取消迟到的 resize/move 防抖回调。
2. 关闭迷你置顶，按当前工作区恢复完整约束/几何和原最大化状态；单窗口始终存在。
3. 卸载迷你栏、挂载完整界面，按保存的体验模式启用资源策略；使用最新播放摘要与浏览锚点恢复。
4. 转换成功再持久化和放开保存。失败返回可操作的迷你栏，保留重试/退出入口。

### 4.3 完整 → 切体验、迷你 → 切体验

完整窗口改变实际资源需求，保持窗口几何；切极简先停任务再卸载视觉内容，切正常先挂载可见结构再按需加载。迷你中只更新体验偏好，资源仍然关闭；返回时应用新偏好。

## 5. 窗口与持久化

- 复用同一 Tauri 主窗口，不能额外保留一个隐藏的完整窗口，也不销毁 WebView 以免断开当前会话。
- `usePlatform` 分离宿主平台和响应式布局；Android 始终移动，桌面迷你始终迷你，其他完整窗口继续现有窄屏规则。不能全局删除移动断点。
- `useWindowPersistence` 增加形态与转换阶段；完整/迷你各有尺寸与位置，转换产生的 resize/move 事件不能视为用户调整，也不能把 560×96 写到旧完整尺寸键。
- 所有 geometry 使用逻辑像素；屏幕标识仅作线索，显示器移除、DPI 改变、工作区缩小时重新限幅，保证返回/更多入口始终可见。
- `desktop_ui_preferences.json` 作为拟定的桌面偏好事实源，由 Rust 版本化校验、原子写入；启动时先读它，再决定可选任务与窗口展示。前端持有运行镜像，通过一次更新接口提交，不再独立维护同名 localStorage 权威值。
- 导入旧 `lumo_window_size` 只作为首次完整尺寸迁移；损坏、NaN、超大/负坐标、未知模式均有默认回退。异常退出保留最后一次成功形态，启动重新限幅。
- 偏好写失败允许本次运行切换，但明确提示“本次有效，未保存”；不能回滚当前播放或反复触发写入。模式 JSON 不含凭据，不绑定曲库备份恢复；是否备份 UI 偏好不在本轮扩展。
- 无历史偏好时用当前完整窗口默认值。冷启动在展示前应用形态；确认读失败后回退，不出现完整工作区先加载再缩小的路径。具体展示时序及权限在 M0 探针校验后落地。

## 6. 资源需求与所有权

派生策略：`visualAllowed = experienceMode === 'normal' && windowForm === 'full'`。这是视觉需求条件，联网仍需既有隐私授权；数据写入、音频和必要系统事件不受它替代。

| 资源 | 正常完整 | 极简完整 | 两种迷你 | 所有者与释放点 |
|---|---|---|---|---|
| 界面封面/艺人图片、取色、模糊/动画 | 可见区域按需 | 不请求/不解码 | 不请求/不解码 | 视图/图片入口，转换时卸载、取消、释放 |
| 在线封面自动补全/缩略图自动回填 | 需求+授权；分批限速 | 暂停新增；在安全边界停已有任务 | 同左 | Rust 视觉任务协调器，不等大事务结束后无限排新批次 |
| 扫描中必要标签读取 | 正常 | 正常 | 用户已发起时继续 | 扫描服务；可选封面加工可延后，但音频标签和完整性不能丢 |
| 列表/详情/专辑艺人数组 | 可见数据窗口 | 可见数据窗口，无图片 DTO | 不持有；仅 dirty 标记 | 浏览状态层，进入迷你释放，返回按需刷新 |
| 当前曲目、进度、音量、模式、缓冲/错误 | 保留 | 保留 | 保留 | 常驻会话层；会话一次初始化，不随视图重建 |
| 权威播放队列、下一首预加载 | 保留 | 保留 | 保留 | Rust 播放核心；不清队列、不重复构建解码器 |
| 歌词 | 已打开时加载 | 文字页显式需求 | 不加载，不保留解析/DOM | 可见歌词消费者；后台无需求停止刷新 |
| 系统媒体通知 | 正常元数据、按需图片 | 文本，空 artwork | 文本，空 artwork | 常驻会话层；切换立即替换已有通知图片 |
| 用户扫描、备份恢复、手动传输 | 保留原语义 | 保留原语义 | 已开始任务继续；交互需返回 | 领域服务；不删除磁盘数据/缓存、不更改联网偏好 |

所有封面入口必须纳入清单：网格、详情、首页、歌曲行、底栏、右栏、沉浸页、歌单弹窗、在线补图、系统通知、自定义协议、扫描/启动回填。不仅修改 `useArtworkSrc`，还要核对内联 Base64 与直接协议 URL。

统一入口关闭新请求，后端对新的非必要图片任务也门禁；已发浏览器协议请求若不能中断，则不显示/不保留结果并记录安全完成，不能承诺强制释放 WebView2 缓存。不能用强制 GC、工作集裁剪或禁用 GPU 制造降内存数字。

旧 `artworkCache` 在当前协议通道不写入，只清这层不能证明收益。应用缓存、浏览器解码、DOM、GPU、SQLite 需分别记录；磁盘缓存无需为模式切换删除。

## 7. 会话与按需数据

- 保留 Rust watcher；核验它在 Windows 无完整视图时持续推进队列。播放事件、媒体键和持久化只初始化一次，视图重复挂载不增加监听/计时器。
- 对外提供轻量会话摘要：当前曲目文字/ID、进度、时长、播放/缓冲/错误、音量、播放模式、队列长度与当前位置、状态版本。迷你不要求整条 `PlaybackQueueStateDto.items`。
- 现有完整队列 API 保持 Android 兼容；浏览队列按需加载，用户手动下一首/上一首仍走 Rust 权威索引，避免两端推进两次。
- 将播放持久状态和浏览缓存的清理边界分开；按最小需要拆 `player.ts`，不把本轮扩大成整个 store 重写。
- 扫描完成、回填和收藏事件在迷你仅更新摘要/版本与 dirty 标记，不调用全量歌曲/专辑/艺人刷新；返回只刷新当前需要的视图。
- 迷你冷启动只恢复会话与必要配置，极简冷启动不取图片 DTO/视觉数据；必要队列仍在 Rust，不能为了省前端对象破坏恢复、随机顺序、长歌单播放。
- 数据窗口初始候选：歌曲最多 3×200 条、文字专辑/艺人最多 3×100 条；M0/M2 验证后调整。用锚点/分页游标支持浏览，全选与 playAll 通过核心查询语义处理，不能变成“仅加载项”。

## 8. 延后决策

SQLite 12×8 MiB 为当前页缓存理论配置，非实测占用。数据库、音频缓冲与扫描并发不随 UI 切换直接重建；M4 若证实占用主要来自这些层，再做独立参数实验与回退。

完整 UI 重写为 Slint/Qt 或原生迷你栏，只有本轮取得同场景数据后再评估，不包含在 M0–M5 中。
