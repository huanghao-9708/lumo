## 1. 执行规则

每项任务由当前实现负责人完成代码、测试与证据，产品负责人复核交互和结果。没有历史 velocity，不给出虚假的 sprint 容量或日期；故事点是相对复杂度，M0 后修订。每项 ≤8 点，拆分后的任务必须能独立评审。

阶段必须顺序通过退出门：M0 → M1 → M2 → M3 → M4 → M5。窗口探针放在 M0，真实迷你入口放在 M3；不能先上线按钮再长期留下数据常驻或移动布局错误。每阶段提交保持可回退，未完成能力不升级 `FEATURE_MATRIX`。

## 3. M0：基线与探针（DM-00）

**故事**：作为实现负责人，我需要区分框架、浏览数据与图片任务的占用，并验证迷你窗口转换，才能确定可衡量的改造顺序。

任务：

- 固定起点 release 二进制、SHA/哈希、设备、曲库规模、显示缩放和 WebView2 版本；先跑当前正常完整窗口 S0/S1/S3/S4，记录本轮基线。
- 列出所有图片入口、生命周期、全局 listener、后台任务与数据数组，记录是否可取消和所有权。
- 临时探针验证单窗口 1200×720 ↔ 560×96、解除/恢复 min constraints、最大化恢复、置顶关闭、DPI/换屏以及权限。探针不作为已发布功能。
- 记录当前会话恢复行为、队列权威与 watcher，在桌面视图卸载后验证播放是否独立推进。

验收：

1. 给定同一 release，重复基线至少 3 次，报告 PWS 中位/P95/峰值和 Private Bytes，不能只保存截图。
2. 给定桌面迷你尺寸，窗口探针必须证明不会被 `<768` 布局和原窗口限幅拉回；失败写明接缝和处理方案。
3. 给定窗口 API 任一步失败，探针能恢复可操作窗口，音频没有被重新启动。
4. 给定现有后台任务，每项有“保留/按需/暂停”分类和可验证观测方式。

退出产物：`M0_执行记录.md`、原始性能数据索引、资源清单、API/权限结论。退出前修订不成立的设计假设。

## 4. M1：状态、会话与资源边界

### DM-01：两维控制器（5 点）

**故事**：作为听歌用户，我希望独立选择体验与窗口形态，并在重启后保留选择。

任务：拟建桌面模式 store/controller 和 Rust 偏好读写服务；处理 schemaVersion、原子写入、旧窗口尺寸迁移；转换串行化/过期 token；初始策略先于可选任务。推荐落点 `src/stores/ui.ts`、新 `src/stores/desktopMode.ts`、`src-tauri/src/services/desktop_preferences.rs` 与命令装配。

验收：

1. 给定正常+迷你，切极简只改体验，返回是极简+完整；四组合均合法。
2. 给定主题为暗色，任意模式/形态转换不改主题。
3. 给定偏好损坏或未知 schema，启动有明确默认回退且不启动失控视觉任务。
4. 给定连续点击/旧响应，只有一次有效转换，失败不持久化成成功状态。
5. 给定写入失败，当前播放和本次切换继续，提示未保存且不循环重试。

### DM-02：常驻会话（8 点）

**故事**：作为用户，我希望完整界面卸载后继续播放，返回时看到准确状态。

任务：梳理 `player.ts`、`src/api/playback.ts`（实施时核验真实文件）、`commands/queue.rs` 和 `services/queue.rs`；按必要边界拆会话/浏览；增加摘要查询和状态版本；根级一次初始化监听与 MediaSession；保留旧队列 API；确保 Rust 权威推进。不得每次模式转换重复 restoreSession 或创建 sink。

验收：

1. 给定正在播放，卸载浏览区并连续播过至少 3 首，顺序正确、无两端重复推进。
2. 给定暂停/Seek/随机/单曲循环/远程缓冲，切换前后语义与位置保持。
3. 给定 30k 长队列，轻量摘要不包含完整 items，迷你控制仍能操作正确曲目。
4. 给定切换 20 次，播放 listener/定时器数量稳定，没有重复事件处理。
5. 给定恢复时摘要版本晚于浏览快照，使用最新会话，旧响应不覆盖它。

### DM-03：资源策略（8 点）

**故事**：作为希望节省资源的用户，我希望极简或迷你时不再为不可见图片和装饰持续付出成本。

任务：新需求策略连接图片/歌词消费者、DTO 与后台任务；后端策略只影响桌面，Android 保持原行为；协议入口观测；启动回填改可暂停的安全批次；通知空 artwork；任务版本/取消检查；释放旧应用缓存但不清磁盘数据/隐私偏好。

验收：

1. 给定极简或迷你稳定态，切歌/滚动不新增界面封面、通知图片与取色任务；记录请求/任务增量为 0。
2. 给定正常完整切极简，有效策略先于异步响应，旧结果不写回已卸载视图。
3. 给定自动回填正在工作，最多允许当前安全批次完成，之后不启动下一批；不能中断数据库事务。
4. 给定用户扫描/备份正在执行，切换不取消核心操作、不丢标签或曲库数据，错误仍可见。
5. 给定在线封面开关关闭，返回正常也不联网；原开关为开启时，极简仅暂停需求，不更改偏好。

M1 退出：无正式新入口也能在测试入口验证四组合策略；会话与策略测试通过，旧默认正常路径和 Android 共享行为回归通过。

## 5. M2：极简完整窗口

### DM-04：极简交互（5 点）

**故事**：作为专注找歌听歌的用户，我希望用清楚的文字列表完成原有操作。

任务：TopBar 菜单；极简首页/文字专辑艺人/无封面详情/播放栏/文字歌词页；token 控制装饰；复用 `shared/trackList`；避免复制业务逻辑；清查设置、弹窗和收藏等遗漏图片入口。

验收：

1. 给定正常完整，菜单切极简后页面实体/排序/播放不变，封面和装饰停止挂载。
2. 给定极简，本地/WebDAV 搜索、歌单、收藏、批量操作都可完成，音质不变。
3. 给定歌词未打开，切歌不加载歌词；显式打开按现有联网授权加载，关闭后停止刷新。
4. 给定日夜主题、长中英文、空标签与 1024×640，文字/按钮清晰且可达。
5. 给定键盘操作，菜单选中态、焦点和关闭行为准确；不新增屏幕阅读障碍。

### DM-05：数据窗口与返回上下文（8 点）

**故事**：作为大曲库用户，我希望进入迷你能释放浏览资源，回来仍能继续原操作。

任务：浏览上下文快照、锚点分页、数组与详情清理、dirty/版本合并；scan-complete/回填事件不再无条件全刷；限定文字列表数据窗口；验证全选和 playAll 的查询语义。该项涉及队列/搜索/选择，需要功能测试后才能启用。

验收：

1. 给定已浏览深页，进入迷你释放 tracks/albums/artists/详情/歌词浏览对象，保留轻量锚点与核心会话。
2. 给定在迷你期间收到多次扫描完成，不拉完整曲库；返回仅按可见需求合并一次刷新。
3. 给定深页/搜索/排序，返回锚点附近恢复，不累计加载此前所有页。
4. 给定筛选后全选/playAll，操作范围仍是完整结果集，不能缩为前端当前窗口。
5. 给定实体删除、多选对象变化、旧异步返回，提供可理解回退且不污染新视图。

M2 退出：正常与极简完整窗口可用；所有封面入口清单均有验收结果；浏览释放可通过计数/堆差分解释。

## 6. M3：迷你栏、窗口与启动

### DM-06：迷你栏（8 点）

**故事**：作为长时间听歌的用户，我希望小播放栏提供必要控制，并随时回到完整界面。

任务：新 `MiniPlayerBar.vue`、完整工作区外壳与根互斥挂载；无需第二播放器；按钮/进度/音量/错误/菜单/拖动区；桌面 mini 优先于响应式断点；全局快捷键避开交互控件。

验收：

1. 给定四组合，迷你始终文字界面、无封面；完整工作区确实卸载而非 v-show 隐藏。
2. 给定音频在播放/暂停/缓冲/失败，上一首/下一首/Seek/音量与返回均可操作。
3. 给定空队列或极长歌名，最小尺寸不遮挡返回/菜单，不主动扫描、不自动播放。
4. 给定拖动和 range/menu 聚焦，按钮不触发窗口拖动，快捷键不吞掉控件键盘行为。
5. 给定编辑/恢复敏感对话框，入口明确不可用及原因；完成后可切换，未保存输入不丢失。

### DM-07：窗口事务（5 点）

**故事**：作为使用不同显示器的用户，我希望迷你尺寸、位置与返回行为可靠。

任务：改 `useWindowPersistence`，两套 geometry、transition lock 和防抖取消；读取平台/布局分离；运行时 constraints、最大化/置顶处理；增加实际所需最小权限。

验收：

1. 给定完整窗口已最大化，进入迷你不被最小约束拉大，返回恢复原最大化状态。
2. 给定转换期间迟到的 resize/move 回调，两套尺寸不互相覆盖、不反复振荡。
3. 给定 100/125/150/200% DPI、多显示器移除，窗口限幅且返回按钮可见。
4. 给定窗口 API/权限失败，恢复上一个可操作形态，保留播放并提示失败。
5. 给定迷你置顶开启，返回完整关闭置顶，再次迷你可恢复迷你偏好。

### DM-08：冷启动与恢复（5 点）

**故事**：作为偏好小播放栏的用户，我希望下次打开直接得到轻量界面。

任务：原生启动前读取偏好并决定窗口形态；迷你启动不调用重型 startup bundle；轻量会话/配置读取；完整恢复按需浏览；异常偏好和写入失败提示；退出、系统恢复、Android 启动回归。

验收：

1. 给定上次成功形态为迷你，冷启动不先挂载完整工作区，不先加载专辑/艺人/封面回填。
2. 给定任一种迷你，返回正确体验/主题及最近成功完整 geometry，数据按锚点恢复。
3. 给定配置缺失/损坏/上次转换崩溃，启动得到可操作窗口，恢复行为不依赖半写入文件。
4. 给定应用重启，队列/进度按原恢复契约，形态偏好不额外触发自动播放。
5. 给定 Android 或技术预览平台，没有误应用 Windows 迷你入口、几何和任务门禁。

M3 退出：四组合端到端可用；冷启动、20 次切换、DPI、错误回退全部通过；代码层确认没有隐藏第二工作区。

## 7. M4：实测与必要调优（DM-09，5 点）

**故事**：作为用户，我希望“极简”和“迷你”带来真实、可重复的资源收益。

任务：按 [验收矩阵](03_验收矩阵与性能实验.md) 跑配对 release 对照；整组采样、请求/对象计数、30/60 分钟连续播放、弱网与长队列；若收益不足定位占用再独立调整，数据库/解码参数不与 UI 修改混在一次实验。

验收：

1. 给定固定设备/曲库，各组合 3 次独立启动和规定场景有原始数据/环境及每进程结果。
2. 给定正常+完整对照，报告极简完整、两种迷你的收益比例和 MiB，不把无差异结果写成显著下降。
3. 给定 60 分钟播放和 20 次转换，资源增长、重复 listener、Private Bytes 均得到解释，音频无可感知断续。
4. 给定查询/首播/Seek/返回，达到暂定性能门槛；必要调参记录查询/等待代价和回退值。
5. 给定未达资源门槛，保留真实失败证据；轻量承诺暂不上线，形成下一项治理结论。

## 9. 代码与提交边界

| 范围 | 主要现有位置 | 新增/修改建议 |
|---|---|---|
| 状态与偏好 | `src/stores/ui.ts`、`src-tauri/src/lib.rs` | 单独模式控制器/偏好服务，避免扩大 ui store |

| 会话与浏览 | `player.ts`、`commands/queue.rs`、`services/queue.rs` | 轻量会话摘要、浏览资源清理、dirty 和锚点恢复 |
| 后台任务与 DTO | `lib.rs`、`commands/library.rs`、repositories | 回填可暂停、启动按需、不发送图片字段 |
| 验证 | 当前 *.spec.ts、Rust 测试、measure-memory | 只加有效行为/资源/故障测试，避免镜像静态模板 |

建议提交按 DM-01 → DM-02 → DM-03 → 极简界面 → 数据窗口 → 迷你组件 → 窗口事务 → 冷启动 → 性能/文档拆分。几何失败会影响可操作性，不能和无关视觉修饰混合提交。

## 10. 风险、停止条件与回退

| 风险 | 预防/处理 | 停止条件 |
|---|---|---|
| 播放会话被卸载或重复初始化 | 根会话常驻、Rust 权威、重复挂载计数 | 音频断续、队列错位或重复切歌 |
| 只隐藏界面，后台继续加载 | 消费者清单、后端门禁、协议计数 | 稳定轻量态仍新增非必要图片任务 |
| 两端偏好或窗口保存竞态 | 原子 JSON、事务 token、冻结/清防抖 | 完整尺寸被迷你覆盖、窗口不可返回 |
| 浏览清理破坏 playAll/选择/随机 | ID/查询语义、长队列回归 | 操作范围变化、顺序变化、选择错误 |
| 自动图片任务暂停导致数据不完整 | 安全批次、核心扫描不停止、延迟补图 | 曲库扫描丢项或迁移/恢复数据受损 |
| 额外系统能力不稳定 | M0 探针、最小权限、置顶只迷你 | 实测窗口 API 无法可靠执行/回退 |
| 框架占用主导，UI 收益不足 | 每进程采样，不预承诺 100 MiB | 轻量目标不达成，转证据与后续方案 |

发现数据/队列正确性阻断时先停新入口，回退该阶段，不清数据库、不删除音乐/封面磁盘文件。已有偏好通过校验回退正常+完整；回退迁移需保证上一版本完整尺寸键仍可用。
