# 验收矩阵与性能实验

> 日期：2026-09-30 · 状态：验收方案已定义，结果全部待测

## 1. 验证原则

验证“显示正确、音频不断、资源真的停止、返回可恢复”四件事。只看截图无法证明卸载，主进程数字无法代表整个产品，开发构建不能与 release 对照混用。延迟阈值为本轮初始工程预算，M0 有证据才能调整，调整必须登记理由。

正常完整记为 NF，极简完整 MF，正常迷你 NM，极简迷你 MM。冷启动 NF/NM 和连续切换 NF→NM 测不同问题，两者都要测；NM/MM 资源策略一致但返回偏好不同。

## 5. 性能实验

### 5.1 环境与口径

- 使用同一测试机、同一曲库与封面分布、同一显示缩放/显示器；固定本地音源与网络条件。空库、1k、10k、30k 分开记录，不混合平均。
- 正式对照使用同一 release 版本，关闭 DevTools、扫描和下载；M0 旧版本用于整体前后对照，新版本四组合用于归因。记录 SHA、工作树状态、二进制哈希与 Windows/WebView2 版本。
- 进程组包括 Lumo 主进程及其归属的全部 WebView2 子进程；人工抽查脚本归属，不能算入其他应用。
- 主指标：整组 Private Working Set（MiB），同时报告分进程、中位/P95/峰值、Private Bytes、CPU、句柄、线程。GPU 专用/共享内存单列，不能只把负担转移到 GPU 后宣布降内存。
- 初始正常/极简完整统一 1200×720；迷你统一 560×96。形态差别是产品实验的一部分；另跑同几何关闭图片的诊断，区分缩窗与任务关闭收益。
- 每组合/场景至少 3 次独立启动，运行顺序轮换；明确冷/暖磁盘缓存、曲目、播放进度、后台任务和预热。不得强制 GC、裁剪工作集或隐藏窗口作为正式主结果。

### 5.2 场景

| ID | 场景 | 时长/样本 | 目的 |
|---|---|---|---|
| D0 | 四组合空库冷启动 | 5 分钟，3 次/组合 | 进程本底、形态展示、重型启动是否发生 |
| D1 | 完整 NF/MF，1k/10k/30k 浏览与搜索 | 各预热 2 分钟后采样 5 分钟 | 数据量斜率、分页与无图收益 |
| D2 | NF/MF 同曲目持续播放 | MP3/FLAC 各 30 分钟 | 体验维度收益 |
| D3 | NM/MM 直接冷启动持续播放 | 同 D2，30 分钟 | 迷你独立启动真实成本 |
| D4 | NF/MF 浏览 10 分钟→迷你静置→返回 | 转换前后连续采样，各稳定 5 分钟 | 已加载资源是否释放、返回是否无界拉取 |
| D5 | 四组合反复切换 | 20 次，再稳定 5 分钟 | 几何竞态、监听/对象累积 |
| D6 | 固定组合持续播放 | 60 分钟，3 次/组合 | 缓存填充后增长/泄漏 |
| D7 | 扫描、WebDAV 播放与备份 | 单列压力实验 | 核心任务兼容与峰值，不能混入稳态收益 |
| D8 | 最小化/后台→恢复 | 30 分钟，单列 | 后台策略与恢复，不能代替可见迷你数字 |

复用 `scripts/measure-memory.ps1`，例如在当前组合已就绪时：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/measure-memory.ps1 -Scenario D2-MF -LibrarySize 30000 -DurationSec 1800 -Notes 'minimal/full; release; visible; no scan'
```

命令示例不表示已跑。原始文件沿用 `scripts/mem-data/` 忽略目录；可审核摘要/匿名数据索引写进阶段记录和现有性能基线。D4/D5 需额外标注转换时间与阶段，脚本若不能标注则用同时间源事件日志对齐后统计。

### 5.3 初始门槛

| 指标 | 初始工程目标 | 处理 |
|---|---|---|
| 必要播放功能 | 全组合无可感知音频断续/队列错位 | 任一失败阻断发布，不能用内存收益抵消 |
| 视觉任务 | R02/R04/R07 通过 | 未通过不接受为有效轻量模式 |
| 30k 库播放稳态 PWS | MF 比 NF 中位下降 ≥20%；NM/MM 比 NF 下降 ≥30% | 各场景 3 次配对差值报告；任一失败需解释，不改成“显著降低” |
| 长期增长 | 第 60 分钟较第 10 分钟稳态增量 ≤20 MiB 且 ≤10% | 分析缓存填充后窗口；Private Bytes 持续增长也必须调查 |
| 切换可操作时延 | 进入迷你 P95 ≤500ms；返回完整基本控制 P95 ≤1s | 30 次转换样本，先可操作再后台按需数据，真实浏览恢复另报 |
| 查找/分页/首播/Seek | 同几何同场景较本轮起点中位恶化不超过 20% | 每类至少 20 次操作；门槛变更记录实测与用户影响 |
| 浏览恢复 | 不从首页反复拉全历史页；首个锚点窗口可见 P95 ≤1.5s | 固定 30k 本地库，无人为网络瓶颈；30 次独立恢复 |
| 长期内存探索 | 可见窗口播放稳态整组 PWS 约 ≤100 MiB | 结果另报；未达成不自动触发原生重写、不影响如实交付 |

20%/30% 是暂定项目目标，不是框架保证。M0 如果发现理论上无法满足，须在实现前记录分项占用、修改目标理由与后续动作；不能在 M4 看到结果后追改阈值让失败变成功。未过收益门仍可作为实验交付，但不得作为已验证低内存能力发布。

## 6. 自动化与人工边界

- 单元/组件：状态组合与转换事务、坏配置/失败写入、策略版本、需求开关、字幕/歌词按需、dirty 合并、锚点/多选语义、窗口限幅、旧防抖回调、重复会话监听。
- Rust：摘要契约、配置校验/原子写入与损坏恢复、后台任务安全暂停、队列继续推进、旧接口兼容。需要真实事件循环/音频设备的部分不以纯函数单测冒充。
- 测试接缝用于注入窗口 API 失败和迟到响应；不写只断言 class 名或复刻实现的测试。
- 人工：音频听感、窗口权限/DPI/换屏、可访问性、系统媒体控制、连续播放、真实 WebDAV、release 内存。已通过的自动化不能替代未完成的人工矩阵。
- 基础检查沿用 `npm run check:ci`；Rust 运行 `cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`。涉及 SQL/参数时补 `cargo test --release --test perf_baseline -- --ignored --nocapture`，在 `src-tauri` 目录执行。
- Android 共享路径按现有清单回归，不凭三平台编译宣布真机或平台行为通过。

## 7. 发布与回退门禁

M5 前：F/W/R 阻断项全通过；窗口转换、冷启动、长队列、数据恢复和隐私授权不变；必要自动化通过；D0–D6 有报告，D7/D8 按本轮触及范围完成；人工未测项具名登记。文案只引用通过场景的数字。

性能未达门槛或资源任务未停：入口留在开发/实验构建，不升级 Stable 承诺；优先定位原因。窗口不可操作/队列错位/数据损坏：关闭新入口并回退对应提交。回退保留模式 JSON但旧版本可忽略，完整尺寸旧键仍可恢复；不得要求用户删库解决 UI 状态。
