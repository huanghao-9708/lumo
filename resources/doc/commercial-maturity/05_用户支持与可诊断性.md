# I5：用户支持与可诊断性

> 优先级：P1  
> 建议周期：5–8 个工程日  
> 建议容量：27 点 Committed，5 点 Stretch  
> 前置：I2 隐私脱敏规则、I3 错误分类  
> 迭代目标：让用户遇到问题时能理解、恢复、反馈，让维护者拿到足够且安全的诊断证据。

## 1. 成功标准

- 用户可以在应用内获得错误原因和下一步操作；
- 本地日志在重启和崩溃后仍可用，且不包含凭据；
- 用户可以主动导出一份结构化、脱敏的支持包；
- 建立安装、导入、WebDAV、恢复、升级的自助文档；
- Issue/反馈能够按模板提供版本、平台、步骤和诊断；
- 建立支持优先级、响应规则和问题关闭标准。

## 2. 用户故事与估算

| ID | 用户故事 | 优先级 | 点数 |
|---|---|---:|---:|
| SUP-001 | 作为用户，我希望错误信息告诉我怎么恢复，而不是只显示内部错误 | High | 5 |
| SUP-002 | 作为用户，我希望主动导出脱敏诊断包，以便快速获得帮助 | High | 8 |
| SUP-003 | 作为新用户，我希望有安装和首次导入指南，以便不依赖开发文档 | High | 5 |
| SUP-004 | 作为维护者，我需要结构化反馈入口，以便稳定复现用户问题 | High | 3 |
| SUP-005 | 作为支持负责人，我需要分级与响应流程，以便优先处理高风险问题 | Medium | 3 |
| SUP-006 | 作为用户，我希望崩溃后知道数据是否安全并能恢复 | High | 3 |

## 3. 详细执行点

### SUP-001：用户可行动错误体系

- [ ] 建立稳定错误码，不直接依赖内部英文错误字符串；
- [ ] 按扫描、播放、WebDAV、数据库、缓存、更新、权限分类；
- [ ] 每个高频错误提供标题、说明、下一步、是否可重试；
- [ ] 401/403 引导重新认证或检查权限；
- [ ] 超时与断网区分，不提示数据已删除；
- [ ] 磁盘满提示清理缓存和所需空间；
- [ ] 数据库错误优先保护现场，不反复自动重试写入；
- [ ] UI 显示可复制错误 ID；
- [ ] 技术细节放入详情或诊断包，不直接压给普通用户；
- [ ] 对主要错误文案进行中文一致性校对。

### SUP-002：本地日志与诊断支持包

- [ ] 使用结构化日志并包含时间、级别、模块、错误码、会话 ID；
- [ ] Release 默认记录必要 INFO/WARN/ERROR，不记录敏感参数；
- [ ] 增加日志滚动、数量上限和保留时间；
- [ ] 注册 panic/crash hook 保存最后错误；
- [ ] IPC 日志继续默认脱敏，并增加敏感字段回归测试；
- [ ] URL 日志移除 userinfo、query token 和敏感路径；
- [ ] 诊断包包含版本、平台、架构、数据库 schema、来源类型、最近错误和日志；
- [ ] 诊断包不包含密码、API Key、完整音乐文件路径、歌词、播放历史明细；
- [ ] 用户导出前展示包含内容并获得主动确认；
- [ ] 支持纯文本/压缩包输出，文件名带时间和匿名会话 ID；
- [ ] 导出失败给出可恢复提示；
- [ ] 用预置秘密值执行自动扫描，确保导出包无泄露；
- [ ] 建立诊断包格式版本，便于后续兼容。

验收标准：

```text
Given 应用中保存了测试密码和 API Key
When 用户导出诊断包
Then 包内搜索不到完整或部分秘密值

Given 应用发生崩溃并重新启动
When 用户查看恢复提示
Then 可以知道上次异常、数据保护状态和诊断导出入口
```

### SUP-003：用户文档中心

- [ ] README 首屏改为面向用户，开发指南下移；
- [ ] 提供正式下载、安装和校验步骤；
- [ ] 提供首次导入本地曲库指南；
- [ ] 提供 WebDAV 配置示例和兼容矩阵；
- [ ] 解释在线歌词、封面和 AI 的隐私行为；
- [ ] 提供备份、恢复和迁移设备指南；
- [ ] 提供升级、回滚和卸载数据保留说明；
- [ ] 提供“歌曲找不到、无法播放、封面缺失、远程卡顿”等 FAQ；
- [ ] 标注支持格式与限制，不扩大底层库理论支持；
- [ ] 文档页面标注适用版本和最后更新时间；
- [ ] 检查所有链接和截图在发布版本有效。

### SUP-004：反馈与 Issue 模板

- [ ] 新增 Bug、兼容性、功能建议、数据风险四类模板；
- [ ] Bug 模板要求版本、平台、复现步骤、预期/实际结果；
- [ ] 数据风险模板提示先停止操作并备份数据库；
- [ ] 安全问题引导私下渠道，不公开披露；
- [ ] WebDAV 问题要求服务端类型和能力信息，不要求提交密码；
- [ ] 增加日志脱敏提醒；
- [ ] 自动标签与优先级初筛规则；
- [ ] 关闭问题时记录修复版本或无法复现原因。

### SUP-005：支持分级与响应流程

- [ ] 定义 S0 数据损坏/安全、S1 核心不可用、S2 功能异常、S3 咨询建议；
- [ ] 定义首响目标和状态更新频率；
- [ ] 定义何时要求诊断、何时要求数据库副本；
- [ ] 数据库副本必须先提供匿名化说明和删除承诺；
- [ ] 建立 Known Issues 列表；
- [ ] 每次发布复盘新增 Issue、逃逸缺陷和平均解决时间；
- [ ] 明确个人项目阶段不承诺 7×24，避免不现实 SLA。

### SUP-006：崩溃恢复体验

- [ ] 启动时检测上次是否正常退出；
- [ ] 崩溃后不立即重复执行高风险迁移/扫描；
- [ ] 提供安全启动选项：暂停扫描、暂停联网、跳过恢复队列；
- [ ] 告知数据库是否通过完整性检查；
- [ ] 提供恢复最近备份或打开诊断位置入口；
- [ ] 连续崩溃达到阈值后进入安全模式；
- [ ] 验证安全模式不删除用户数据。

## 4. 支持指标

| 指标 | Beta 目标 |
|---|---:|
| 可复现 Bug 占比 | ≥ 70% |
| 有版本/平台信息的报告 | ≥ 90% |
| 诊断包脱敏失败 | 0 |
| S0/S1 未分级问题 | 0 |
| 文档可解决的重复问题 | 持续上升 |
| 崩溃后可恢复启动率 | 100% |

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| 日志过多损害隐私和磁盘 | 默认最小、滚动限制、用户主动导出 |
| 错误码过度工程化 | 先覆盖高频和高风险链路 |
| 文档快速过时 | 标注适用版本，发布门禁检查关键页面 |
| 用户上传含私人曲库信息 | 导出前脱敏、预览内容、提供删除政策 |
| 安全模式本身未经验证 | 纳入 E2E 和发布冒烟 |

## 6. 退出清单

- [ ] 高风险错误均有稳定错误码和用户行动建议；
- [ ] 日志可跨重启保留并受容量限制；
- [ ] 诊断包自动脱敏测试通过；
- [ ] 崩溃后安全启动和数据检查可用；
- [ ] 用户安装、导入、WebDAV、备份恢复、升级文档完整；
- [ ] Issue 与安全报告模板已启用；
- [ ] 支持分级和 Known Issues 流程已演练；
- [ ] 不依赖开发者控制台才能诊断常见问题。
