# I2：安全、隐私与供应链治理

> 优先级：P0  
> 建议周期：7–10 个工程日  
> 建议容量：32 点 Committed，5 点 Stretch  
> 前置：I0 联网清单、I1 CI 基线  
> 迭代目标：将“尊重隐私”从产品口号变成可审计、可测试、可响应的安全体系。

## 1. 成功标准

- 威胁模型覆盖本地文件、数据库、WebDAV 凭据、AI Key、IPC、更新与第三方请求；
- CSP 不再为空，所有必要权限遵循最小化；
- XOR 混淆退出凭据保护主路径；
- 高危依赖风险清零或有正式豁免；
- 所有外联默认状态、发送数据和服务方对用户透明；
- 建立漏洞报告、处置、发布与用户通知流程。

## 2. 用户故事与估算

| ID | 用户故事 | 优先级 | 点数 |
|---|---|---:|---:|
| SEC-001 | 作为用户，我希望凭据被平台安全机制保护，以便设备文件泄露时密码不被轻易恢复 | Critical | 8 |
| SEC-002 | 作为用户，我希望应用只执行必要的网页和 IPC 能力，以便降低注入攻击面 | Critical | 5 |
| SEC-003 | 作为隐私敏感用户，我希望明确控制联网行为，以便知道哪些数据离开设备 | Critical | 5 |
| SEC-004 | 作为发布者，我需要持续发现依赖风险，以便不把已知漏洞带入安装包 | High | 5 |
| SEC-005 | 作为安全报告者，我需要明确的报告渠道，以便漏洞被私下、及时处理 | High | 3 |
| SEC-006 | 作为维护者，我需要第三方组件与服务清单，以便处理许可证和服务变更 | High | 3 |
| SEC-007 | 作为团队，我需要安全发布门禁，以便关键风险不能被普通发布绕过 | High | 3 |

## 3. 详细执行点

### SEC-001：凭据生命周期升级

- [ ] 盘点 WebDAV 来源密码、备份 WebDAV 密码、AI API Key 的创建、读取、迁移、删除路径；
- [ ] Windows 使用 Credential Manager；
- [ ] macOS 使用 Keychain；
- [ ] Android 使用 Keystore 包装的数据加密密钥；
- [ ] Linux 明确选用 Secret Service 或安全降级策略；
- [ ] 使用标准认证加密算法，禁止自定义 XOR 作为安全方案；
- [ ] 密文必须包含版本、随机 nonce、认证标签和算法标识；
- [ ] 数据库只存不可读引用或认证密文，不存可直接复原的通用固定密钥密文；
- [ ] 对旧 `v2:seal`、`v3:seal` 数据实施一次性懒迁移；
- [ ] 迁移成功后安全删除旧值；
- [ ] 密钥缺失时返回 `NEEDS_REAUTH`，不得静默清空或循环失败；
- [ ] 删除来源时同步删除系统凭据；
- [ ] 卸载、备份恢复、跨设备迁移的凭据行为写入文档；
- [ ] 增加篡改密文、错误 nonce、密钥丢失和旧格式迁移测试。

验收标准：

```text
Given 攻击者只获得 lumo.sqlite
When 检查所有凭据字段
Then 无法直接恢复 WebDAV 密码或 AI Key

Given 旧版本凭据仍可读取
When 用户首次成功使用该凭据
Then 凭据被迁移到新存储，旧密文不再保留

Given 密文被修改任意字节
When 应用尝试解密
Then 认证校验失败，不返回部分明文
```

### SEC-002：Tauri、WebView 与 IPC 最小权限

- [ ] 根据实际资源制定 CSP；
- [ ] 默认禁止任意远程脚本、iframe 和未声明连接；
- [ ] 为 WebDAV、AI 自定义端点评估是否应由 Rust 后端代理而非放宽 WebView CSP；
- [ ] 检查 Tauri capability，只保留当前窗口必要权限；
- [ ] Debug 命令不得进入 Release 构建；
- [ ] IPC 命令检查输入长度、路径、URL scheme 和 ID 合法性；
- [ ] 阻止 `file://`、危险自定义 scheme 和意外 localhost 访问；
- [ ] 对自定义 artwork 协议增加严格路径/ID校验；
- [ ] 建立 CSP 与 capability 自动快照检查；
- [ ] 验证外部 URL 只能通过受控 opener 打开。

### SEC-003：隐私政策与可验证联网控制

- [ ] 以 I0 联网清单为基础起草隐私政策；
- [ ] 明确哪些数据永久留在本地；
- [ ] 明确歌词、封面、AI、更新检查分别发送什么；
- [ ] 明确第三方服务由谁运营，Lumo 是否保存响应；
- [ ] 所有在线增强功能默认关闭；
- [ ] 首次开启前展示简短告知，不使用预勾选；
- [ ] 关闭后立即停止后续请求；
- [ ] 提供清除在线元数据缓存与 AI 配置的方法；
- [ ] 设置页提供“联网行为说明”入口；
- [ ] 使用代理/抓包验证全新安装默认离线口径；
- [ ] 将抓包域名结果作为发布证据归档。

### SEC-004：依赖与构建供应链

- [ ] npm CI 执行生产依赖与完整依赖审计；
- [ ] Rust 引入 RustSec 审计；
- [ ] 处理当前 nanoid、postcss 风险并记录升级影响；
- [ ] 区分构建期漏洞与运行时可利用漏洞；
- [ ] 对无法立即升级的风险记录 CVE、影响、缓解、负责人和截止日期；
- [ ] 启用自动依赖更新，但按前端/Rust/Actions 分组；
- [ ] GitHub Actions 使用受信任版本，关键发布 Action 评估固定 commit SHA；
- [ ] 生成 CycloneDX 或 SPDX SBOM；
- [ ] 发布产物关联依赖锁文件和构建提交；
- [ ] 禁止未锁定的构建工具在发布时动态安装 latest；
- [ ] 建立每月一次依赖升级窗口。

### SEC-005：漏洞响应机制

- [ ] 新增 `SECURITY.md`；
- [ ] 提供私下报告渠道，不要求公开 Issue 披露；
- [ ] 定义确认、分级、修复、发布、披露时间；
- [ ] 定义 P0/P1 安全事件负责人；
- [ ] 建立密钥泄露、恶意更新、第三方 API 泄露应急预案；
- [ ] 模拟一次凭据泄露响应；
- [ ] 确保安全修复能够绕过常规节奏但不能绕过最小验证。

### SEC-006：第三方服务与许可证治理

- [ ] 生成 Rust、npm、Android 依赖许可证清单；
- [ ] 检查许可证兼容性和 Notice 要求；
- [ ] 记录网易云、iTunes、LRCLIB、GitHub API 的用途、条款、限流与替代策略；
- [ ] 评估封面和歌词缓存的版权与再分发边界；
- [ ] 不将无 SLA 的第三方接口描述为可靠核心服务；
- [ ] 为第三方中断定义本地降级，不影响本地播放；
- [ ] 输出 `THIRD_PARTY_NOTICES.md`。

### SEC-007：安全发布门禁

- [ ] 高危依赖默认阻断 Stable；
- [ ] 凭据日志扫描加入 CI；
- [ ] 检查构建产物不包含 `.env`、测试凭据、keystore 或调试端点；
- [ ] 对安装包执行恶意软件/基础静态扫描；
- [ ] 发布评审必须附 SBOM、审计结果和例外清单；
- [ ] 所有安全豁免必须有过期时间。

## 4. 威胁模型最小范围

| 资产 | 主要威胁 | 必须验证的控制 |
|---|---|---|
| 本地音乐文件 | 误删、误改、路径穿越 | 只读、路径规范化、非侵入测试 |
| SQLite 数据库 | 损坏、覆盖、恶意快照 | 完整性、schema 校验、备份回滚 |
| WebDAV 凭据 | DB/日志/内存泄露 | 安全存储、脱敏、生命周期管理 |
| AI Key | IPC/日志/数据库泄露 | 钥匙串、最小返回、清除能力 |
| 更新包 | 供应链替换、降级 | 签名、校验、版本策略、回滚 |
| WebView | XSS、远程脚本、危险跳转 | CSP、最小 capability、受控 opener |
| 第三方元数据 | 隐私泄露、服务失效 | 默认关闭、告知、降级、超时 |

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| 凭据迁移导致用户失去连接 | 迁移前保留可回退副本，成功验证后删除旧值 |
| CSP 影响图片或 IPC | 逐域逐能力收紧，配合 E2E 回归 |
| Linux 安全存储差异 | 明确支持矩阵，不伪装成所有平台同等级 |
| 第三方条款不允许当前用法 | 可配置替代服务或暂时降级对应在线增强 |
| 自动升级依赖引入回归 | 依赖 PR 必须通过完整测试和平台冒烟 |

- [ ] 威胁模型完成并评审；
- [ ] CSP 不再为空；
- [ ] 主路径不再使用 XOR 保护凭据；
- [ ] 旧凭据迁移和失败恢复测试通过；
- [ ] 默认离线抓包验证通过；
- [ ] 隐私政策、Security Policy、第三方清单完成；
- [ ] SBOM 可从 CI 生成；
- [ ] 高危依赖风险清零或有正式时限豁免；
- [ ] 安全门禁阻断测试通过。
