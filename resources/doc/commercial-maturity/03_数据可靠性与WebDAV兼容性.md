# I3：数据可靠性与 WebDAV 兼容性

> 优先级：P0  
> 建议周期：7–10 个工程日  
> 建议容量：34 点 Committed，5 点 Stretch  
> 前置：I1 测试基础设施  
> 迭代目标：证明扫描、数据库升级、备份恢复和远程播放在失败条件下不会损坏用户数据。

## 1. 成功标准

- 任何扫描错误不会把未成功遍历的曲库误标为缺失；
- 迁移、恢复、缓存下载均使用可回滚的事务或原子替换；
- WebDAV 在支持 Range、不支持 Range、弱网、认证失败等情况下有明确行为；
- “数据备份恢复”具备校验、版本兼容、回滚和用户提示；
- 性能声明有固定数据集和可重复基准，不再依赖单次主观观察。

## 2. 用户故事与估算

| ID | 用户故事 | 优先级 | 点数 |
|---|---|---:|---:|
| DATA-001 | 作为用户，我希望来源暂时不可访问时曲库记录不会消失 | Critical | 8 |
| DATA-002 | 作为用户，我希望升级和恢复失败时仍能回到原数据 | Critical | 8 |
| DATA-003 | 作为 WebDAV 用户，我希望不同服务端能力有明确降级 | Critical | 8 |
| DATA-004 | 作为用户，我希望缓存损坏或磁盘不足不会破坏播放与数据库 | High | 5 |
| DATA-005 | 作为维护者，我需要可重复性能基准，以便优化不靠感觉 | Medium | 5 |

## 3. 详细执行点

### DATA-001：扫描一致性与故障模型

- [ ] 为每次扫描生成唯一 job id 和 generation；
- [ ] 同一来源同时只允许一个活跃扫描；
- [ ] 记录扫描状态：pending、running、completed、failed、cancelled；
- [ ] 区分“文件确实删除”和“本次未能访问”；
- [ ] 只有完整成功遍历后才提交 missing/tombstone；
- [ ] 根目录失败时不修改现有可见状态；
- [ ] 子目录失败时记录部分失败并保留旧数据；
- [ ] 支持取消，并确保取消后不会执行最终缺失标记；
- [ ] 标签解析失败只影响单文件，不中止或污染整个来源；
- [ ] 更新来源 `last_error` 与最后成功扫描时间；
- [ ] UI 区分成功、部分成功、失败和取消；
- [ ] 为断网、权限撤销、目录删除、文件锁定、非法标签建立测试。

验收标准：

```text
Given 已索引 10,000 首远程歌曲
When WebDAV 在扫描开始时不可访问
Then 现有歌曲仍可见，来源显示失败，不产生 10,000 条 missing

Given 扫描中途被取消
When 用户返回曲库
Then 已有数据保持一致，取消状态可见，后续可重新扫描
```

### DATA-002：数据库升级、备份与恢复

- [ ] 在恢复前验证文件类型、大小、SQLite header；
- [ ] 执行 `integrity_check` 与 `foreign_key_check`；
- [ ] 验证 schema 版本不高于当前客户端可识别版本；
- [ ] 对历史 schema 执行迁移后再进入 live DB；
- [ ] 恢复前创建本地可识别备份；
- [ ] 恢复过程中失败必须自动回滚；
- [ ] 恢复后重新验证关键表与配置；
- [ ] 恢复成功前不删除回滚副本；
- [ ] 明确定义回滚副本保留时长和空间上限；
- [ ] 防止远程空文件、HTML 错误页或非 Lumo DB 覆盖本地；
- [ ] 对远程快照增加 checksum 元数据；
- [ ] 上传采用临时文件再 rename/move，服务端不支持时明确降级；
- [ ] 上传后重新下载头部或完整文件验证；
- [ ] 恢复 UI 展示影响、备份位置和不可合并语义；
- [ ] 完成断电/进程终止模拟测试。

### DATA-003：WebDAV 兼容实验室

- [ ] 选择至少三类服务端：NAS/Nextcloud 类、对象/网盘代理类、标准测试服务器；
- [ ] 为每类记录认证、PROPFIND、UTF-8 路径、特殊字符、Range、ETag、MOVE 能力；
- [ ] 能力探测结果持久化并设置复测策略；
- [ ] Range 返回 206 时严格验证 Content-Range；
- [ ] 服务端忽略 Range 返回 200 时降级为完整缓存，不从错误偏移解码；
- [ ] 401/403 显示重新认证或权限错误；
- [ ] 404 区分文件删除与 URL 编码错误；
- [ ] 429/5xx 实施有限退避，不无限重试；
- [ ] 配置连接、读取和总超时；
- [ ] TLS 错误不建议用户直接关闭证书校验；
- [ ] HTTP 明文源显示明确风险提示；
- [ ] 弱网中断支持安全重试或从头下载；
- [ ] 下载临时文件使用 `.part`，校验成功后原子改名；
- [ ] 输出公开兼容矩阵和已知限制。

### DATA-004：缓存与磁盘异常

- [ ] 缓存写入前检查可用空间或处理 ENOSPC；
- [ ] 缓存文件记录预期大小、来源和校验状态；
- [ ] 不完整缓存不得作为可播放完整文件；
- [ ] 启动时清理过期 `.part` 文件；
- [ ] 缓存淘汰不得删除正在播放文件；
- [ ] 数据库记录与磁盘文件不一致时可自愈；
- [ ] 用户清理缓存不影响曲库、歌单和收藏；
- [ ] 测试只读目录、磁盘满、权限变化、文件被占用；
- [ ] 错误信息说明用户可采取的操作。

### DATA-005：可重复性能基准

- [ ] 建立 1k、10k、30k 曲库的匿名化或生成式数据集；
- [ ] 定义冷启动、热启动、首次扫描、增量扫描、搜索、首播、切歌指标；
- [ ] 分开测量本地、局域网 WebDAV、弱网 WebDAV；
- [ ] 固定硬件、系统、构建模式和测量方法；
- [ ] 每个指标至少运行 5 次并记录中位数与 P95；
- [ ] 将明显回退阈值加入夜间 CI 或发布门禁；
- [ ] 对安装包、内存占用和启动时间的公开声明使用实测区间；
- [ ] 输出 `PERFORMANCE_BASELINE.md`。

## 4. 故障注入矩阵

| 场景 | 预期行为 |
|---|---|
| 扫描中断网 | 旧记录保留，状态为失败/部分失败 |
| 扫描中取消 | 不提交缺失标记，可再次启动 |
| WebDAV 返回错误 Range | 停止当前解码并清晰报错/降级 |
| 恢复文件为空 | 拒绝恢复并删除临时文件 |
| 恢复文件 schema 过新 | 拒绝覆盖，提示需要新版客户端 |
| 恢复中断电 | 下次启动可选择原库或已验证备份 |
| 缓存磁盘满 | 当前库不损坏，提示释放空间 |
| 远端同名文件被替换 | 根据 ETag/mtime/size 使旧缓存失效 |
| 凭据失效 | 不清空曲库，提示重新认证 |

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| 服务端差异无法穷举 | 能力探测 + 明确降级 + 公开已知限制 |
| 整库恢复始终存在覆盖风险 | 强提示、本地备份、校验、回滚；不称为合并同步 |
| 大型 fixture 使 CI 过慢 | PR 用小数据，夜间跑 30k 基准 |
| Windows 文件锁影响恢复 | 使用 SQLite Backup API，并做平台专项测试 |
| 性能优化改变数据语义 | 正确性测试必须先于性能基准通过 |

## 6. 退出清单

- [ ] 扫描失败、部分失败和取消不会错误丢失曲库；
- [ ] 历史数据库升级、恢复和回滚测试全部通过；
- [ ] 三类 WebDAV 服务完成兼容验证；
- [ ] Range、超时、认证和弱网行为明确；
- [ ] 缓存异常不会损坏数据库或阻断本地播放；
- [ ] 备份恢复 UI 与文档不再暗示合并同步；
- [ ] 性能基准可重复，公开声明有证据；
- [ ] 没有未处理的数据损坏类 P0 缺陷。
