## 2. 详细问题与修复建议

### MOB-001｜P0：Android 媒体兼容库依赖缺失

- 定位：`src-tauri/gen/android/app/build.gradle.kts`、`src-tauri/gen/android/app/src/main/java/com/hao/lumo/MediaPlaybackService.kt`
- 现状：播放服务引用 `androidx.media.app.NotificationCompat.MediaStyle` 与 `android.support.v4.media.session.MediaSessionCompat`，但 Gradle 依赖列表没有显式声明 `androidx.media:media`。
- 风险：Android Kotlin 编译可能出现未解析引用，阻断 Debug/Release APK 产出。
- 修复建议：显式添加与当前 AndroidX 版本兼容的 `androidx.media:media` 依赖；或者改用纯 Android 平台的 `MediaStyle` / `MediaSession` API，并以 `assembleDebug` 和 Release 构建验证。
- 验收：Android Debug、Release 均可构建；通知栏显示曲目、上一首、播放/暂停、下一首控制。

### MOB-002｜P1：移动端缺少二级页面导航入口

- 定位：`src/components/mobile/MobileLayout.vue`、`src/components/mobile/MobileHeader.vue`
- 现状：底部 Tab 只进入“曲库”和“收藏”根页；右上角“更多”按钮没有点击事件。专辑、艺术家、文件夹、播放列表、最近播放、收藏专辑和收藏歌手缺少可发现的入口。
- 风险：功能虽然已有组件，用户无法从正常移动端流程访问，等同未交付。
- 修复建议：实现曲库/收藏的页面选择菜单、分段控件或抽屉导航；保留当前页及返回栈状态。
- 验收：全新启动后，用户无需搜索即可进入以上全部页面；Android 返回键能逐级返回根页。

### MOB-003｜P1：队列播放失败被吞掉

- 定位：`src-tauri/src/commands/queue.rs`
- 现状：`playback_set_queue` 与 `playback_advance` 用 `let _ = internal_play_item(...)` 丢弃播放失败。前端在调用前已经把 `isPlaying` 设为 `true`。
- 触发场景：文件被删除、存储权限失效、远端不可达且无缓存、无效 `media_file_id`。
- 风险：界面显示正在播放但没有声音，队列索引与底层 Sink 状态不一致，后续播放/暂停难以恢复。
- 修复建议：传播播放错误；仅在实际启动成功后提交播放状态；前端展示可重试错误并恢复到暂停状态。切歌失败时应决定“停在当前项”或“跳过不可播项”，并统一实现。
- 验收：上述异常场景不会显示假播放；恢复网络、权限或文件后可正常重试。

### MOB-004｜P1：系统媒体控制与应用状态不同步

- 定位：`src-tauri/src/services/platform.rs`、`src-tauri/src/commands/queue.rs`
- 现状：通知栏、耳机按键和音频焦点回调直接操作 `PlaybackManager`，绕过常规播放命令；自动 gapless 切歌只发前端曲目事件，没有刷新 Android 前台通知。
- 风险：
  - 从通知栏暂停后，应用内仍显示播放中；
  - 通知栏仍显示暂停按钮或错误的常驻状态；
  - 自动切到下一首后，锁屏/通知栏仍显示上一首元数据；
  - 播放进度和会话持久化可能滞后。
- 修复建议：收敛为单一播放状态机。原生回调应调用统一的 pause/resume/stop/advance 逻辑，或发出明确的状态事件；每次曲目、播放状态变化均同步 MediaSession、前台通知、前端 Store 和持久化状态。
- 验收：通知栏、耳机、蓝牙、来电焦点、应用内按钮任一入口操作后，四处状态在 1 秒内一致；自动切歌后通知元数据正确更新。

### MOB-005｜P1：WebDAV 密码未被安全加密

- 定位：`src-tauri/src/commands/scanner.rs`、`src-tauri/src/services/sync.rs`、`src-tauri/src/services/secret.rs`
- 现状：密码采用“固定或可推导密钥 + 重复 XOR + Base64”。Base64 只是编码；密钥可从应用代码、固定种子或应用路径推导，无法抵抗数据库、备份文件或 APK 被获取的情况。
- 风险：WebDAV 密码可被恢复；同步快照还会携带可恢复的同步配置密码。
- 修复建议：Android 端使用 Android Keystore 保存设备凭据；桌面端使用系统凭据库。同步快照不应包含可恢复密码，应在新设备恢复后要求重新认证。迁移旧数据时应重新写入安全存储并清理旧字段。
- 验收：数据库和 WebDAV 快照中不再存在可还原密码；跨设备恢复后需重新输入密码；日志和 IPC 返回值不暴露密码。

### MOB-006｜P2：新建 WebDAV 来源可能扫描到旧记录

- 定位：`src/components/mobile/MobileWebdavSourceEditor.vue`
- 现状：创建成功后用“相同 URL **或** 相同名称”从来源列表反查新记录。存在重名、重复 URL 或列表尚未刷新的情况下，可能选中旧来源。
- 修复建议：让 `addSource` 返回后端创建的 `id`，并直接按该 `id` 调用扫描；不要依赖名称或 URL 反查。
- 验收：连续添加同名来源、同 URL 来源时，只扫描本次刚创建的来源。

### MOB-007｜P2：设置页返回键拦截器泄漏

- 定位：`src/components/mobile/MobileSettings.vue`
- 现状：设置页注册了 `registerBackHandler`，但组件卸载时未调用注销函数。页面通过 `v-else-if` 切换，会反复挂载和卸载。
- 风险：无效闭包累计；未显示的旧弹窗状态可能消费一次 Android 返回操作。
- 修复建议：保存 `registerBackHandler` 的返回函数，并在 `onBeforeUnmount` 中调用；临时弹层同样遵循注册—注销生命周期。
- 验收：反复切换设置页后，返回键每次只触发当前可见页面的一次处理。

## 6. 修复执行记录（2026-09-01）

1. **MOB-001**：在 `src-tauri/gen/android/app/build.gradle.kts` 中显式添加 `androidx.media:media:1.7.0`，修复 `MediaStyle` 与 `MediaSessionCompat` 依赖缺失。
2. **MOB-002**：改造 `src/components/mobile/MobileHeader.vue`，为“曲库”和“收藏”根页增加标题下拉指示器与更多按钮交互，弹出底部 ActionSheet 切换全部二级视图，并支持 Android 返回键多级退回根页。
3. **MOB-003**：在 `src-tauri/src/commands/queue.rs` 中将 `internal_play_item` 失败向调用方传播，触发 `playback-error` 事件并将前台通知重置为非播放态；在 `src/stores/player.ts` 中捕获异常，重置 `isPlaying = false` 与 `isBuffering = false`，彻底消除假播放。
4. **MOB-004**：在 `src-tauri/src/services/platform.rs` 中重构原生 `lumoNativeMediaAction`，在处理 play/pause/stop 时同步调用 `update_foreground` 并向前端 emit `playback-status-changed` 事件；在 `queue_watcher_loop` 自动 gapless 切歌或推进切歌时，立即刷新前台通知元数据；前端监听 `playback-status-changed` 与 `playback-error` 实现全局双向状态一致。
5. **MOB-005**：在 `src-tauri/src/services/secret.rs` 与 `scanner.rs` 中引入本地随机设备私钥（`.device_secret`），使凭据无法从应用源码或外部推导；在 `src-tauri/src/services/sync.rs` 的 `create_snapshot` 中，将导出的快照数据库密码字段（`sync_config.password_encrypted` 与 `sources.credential_ref`）清空脱敏，杜绝快照云端泄露风险。
6. **MOB-006**：修改 `src/stores/player.ts` 的 `addSource` 方法返回后端的数字 ID；在 `MobileWebdavSourceEditor.vue` 中直接传入该 ID 触发扫描，避免根据名称/URL 反查旧记录。
7. **MOB-007**：在 `src/components/mobile/MobileSettings.vue` 中保存 `registerBackHandler` 的注销句柄，并在 `onBeforeUnmount` 钩子中执行注销，防止多次进入设置页产生返回拦截器泄漏。
