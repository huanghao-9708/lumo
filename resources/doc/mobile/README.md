## 命名约定说明

为避免与既有里程碑命名冲突，移动端迭代统一使用 **MA 前缀**（Mobile-Android）：

- `M1-M6`：已被移动端 **UI 自适应布局**里程碑占用（提交 `8f89da0`，指纯前端响应式层，已完成）。
- `M0-M5`：已被桌面端审计执行计划占用（见 [`../项目代码审计与执行计划_2026-08-28.md`](../项目代码审计与执行计划_2026-08-28.md) 第 6 节）。
- `MA0-MA5`：本移动端计划。MA1-MA5 的 UI 层建立在已完成的 M1-M6 组件之上，二者不是同一批工作。

## 维护规则

1. **迭代启动时**：将对应 MA 文档头部「状态」改为「进行中」，并按需细化当期任务粒度。
2. **任务完成时**：勾选该文档中的验收清单项，如有偏差在「执行记录」小节追加记录（日期 + 实际做法 + 偏差原因）。
3. **迭代结束时**：更新 `00_移动端总体迭代计划.md` 中迭代总览表的状态列与风险登记册；新发现的风险项补入登记册。
4. **任何关键决策变更**（如音频方案降级、存储策略改选）：在总体计划的「技术决策记录」表中追加一行，禁止直接删除旧行（保留决策演变轨迹）。

## 一句话概述

> 先用一周（MA0）把 Android 交叉编译、TLS、原生音频输出三大不确定性变成明确结论，再以「本地闭环 → 后台播放 → WebDAV 同步 → 体验打磨 → 发布」五个可独立交付的迭代，把桌面端 v1.1.1 的能力完整搬到 Android 真机上。
