# Lumo 移动端总体迭代计划（Android）

> 状态：执行中　|　建立：2026-08-31
> 计划基线：`app` 分支，桌面端 v1.1.1（提交 `d8db3b6`）
> 估算假设：1 名熟悉 Vue、Rust、Tauri 的全栈工程师；工期含 25%～30% 不确定性缓冲（P80）
> 配套文档：本目录下 MA0～MA5 六份执行文档，每迭代一份，含任务分解、技术方案、验收清单

## 1. 背景与目标

桌面端（Windows）已完成 v1.1.1 并稳定运行：本地/WebDAV 双引擎播放、统一曲库、收藏/歌单/历史、歌词、封面缓存、跨设备备份均已在代码闭环（详见 [`../项目代码审计与执行计划_2026-08-28.md`](../项目代码审计与执行计划_2026-08-28.md) 及其 §11 已执行修复）。本计划的目标是**在不推翻现有架构的前提下，把 Lumo 带到 Android 手机上**，复用现有的 Rust 后端、Vue 前端与 SQLite 数据模型。

### 1.1 移动端 v1 产品定义

**一句话**：Android 手机上完整可用的本地优先音乐播放器——本地曲库 + WebDAV 曲库 + 后台/锁屏播放，与桌面端共享同一套数据格式与 WebDAV 生态。

**目标（In Scope）**

1. 本地音乐：授权 → 添加目录 → 扫描 → 浏览（歌曲/专辑/艺术家/歌单/收藏）→ 播放（含 gapless）。
2. 后台播放：锁屏/灭屏连续播放，通知栏与锁屏媒体控制（播放/暂停/上一首/下一首/进度）。
3. WebDAV：移动端管理 WebDAV 来源，扫描、流播、本地缓存二播零网络。
4. 数据：WebDAV 备份/恢复（沿用桌面端「实验性备份/恢复」定位，不自动同步）。
5. 体验：LDL 移动端视觉规范落地真机（安全区、手势、触感、暗色模式）。
6. 发布：CI 产出签名 APK，通过 GitHub Releases 分发。

**非目标（Out of Scope，v1 明确不做）**

- iOS / 鸿蒙 / Wear / 车机适配。
- 平板/折叠屏双栏布局（v1 强制移动单栏布局，宽屏策略见 MA4-7）。
- Google Play 上架（含隐私政策、商店资产、审核流程；仅侧载分发，Play 评估后置）。
- 移动端在线元数据（LRCLIB/iTunes，桌面已默认关闭，移动端保持关闭）。
- 记录级自动同步/多端合并（继承桌面审计 P1-09 结论：先做安全备份，合并同步是 V1.1+ 的事）。

### 1.2 成功指标

| 指标 | 目标值 | 度量方式 |
|---|---|---|
| 冷启动（中端机，点图标 → TabBar 可交互） | ≤ 2.5s | 真机计时（MA4 验收） |
| 5000 首曲库列表滚动 | 无可感知掉帧（≥50fps 主观流畅） | chrome://inspect 帧率采样 |
| 后台连续播放（灭屏） | ≥ 30 分钟不断流（抽样 8 小时不被杀） | MA2/MA5 真机测试 |
| 播放时 CPU/内存 | 空闲态内存 ≤ 200MB（LDL 桌面目标 80MB 的移动放宽值） | adb shell dumpsys meminfo |
| 真机冒烟 | ≥ 4 台设备（Android 9/12/14/15）全通过 | MA5 发布检查清单 |

### 2.3 与桌面端计划的衔接

- 桌面审计 M0（止血）已按 §11 完成修复，移动端计划以此为基线。
- 桌面审计遗留项中，**与移动端交叉的部分**在此合并处理，避免重复开发：
  - W07 缓存分层/LRU：移动侧的缓存上限与设置入口在 MA3-3 落地，接口与桌面线对齐；
  - W09 CI：MA5 扩展现有 release workflow 增加 Android job（P2-06 的「先验证后发布」原则同样适用）；
  - W11 keyring：MA3-4 的 Android Keystore 方案是 W11 抽象 `SecretStore` 的移动端实现，桌面侧按桌面计划推进，两端共享 trait 设计；
  - P1-06 离线降级：MA3-6 在移动端消费 `isOnline` 并落地置灰 UI。
- 桌面端继续独立推进的质量项（clippy/fmt 清零、Rust 测试补齐）**不阻塞**移动端，但移动端所有改动的门禁是：Windows 构建 + 现有测试不回退（各 MA 文档验收均含此条）。

## 3. 关键技术决策记录（ADR 摘要）

> 详细方案见对应 MA 文档。决策变更时在此追加新行，不删旧行。

| ADR | 决策点 | 结论 | 理由 | 状态 | 归属 |
|---|---|---|---|---|---|
| ADR-1 | Android TLS 栈 | ~~reqwest 切换 `rustls-tls-native-roots`~~ **修订：`rustls-no-provider` + 进程内安装 ring 后端** | reqwest 0.13 默认后端已是 aws-lc-rs（非 native-tls），其 C 依赖 aws-lc-sys 无法交叉编译 Android（需 cmake）；ring 纯 Rust 全平台一致；证书根由 rustls-platform-verifier 提供（Android 走系统信任库） | **已生效**（2026-08-31 模拟器验证，见 MA0 偏差 1） | MA0 |
| ADR-2 | 音频输出栈 | 继续用 rodio + cpal(oboe)；需两项配套修复（libc++ 链接 + ndk_context 初始化，见 ADR-11/ADR-10） | 模拟器验证：PlaybackManager 初始化成功、测试音播放链路无 panic；真机听感与 44.1kHz 变调检查 MA1 复验 | **Go**（模拟器；真机听感 MA1 复验） | MA0 |
| ADR-3 | 后台播放架构 | 播放队列镜像下沉 Rust + Kotlin 前台服务（通知/MediaSession）+ 音频焦点 | WebView 后台必冻结，前端轮询驱动切歌的现有架构在移动端必断；Kotlin 只做系统集成，解码留在 Rust，避免双播放器 | 已定 | MA2 |
| ADR-4 | 本地存储访问 | 运行时申请 `READ_MEDIA_AUDIO`(API33+)/`READ_EXTERNAL_STORAGE`(≤32)，路径直读（walkdir 不变）；`MANAGE_EXTERNAL_STORAGE` 仅作设置页兜底开关；SAF/MediaStore 否决 | 路径直读零改动复用扫描器；SAF 返回 content:// URI 与 `std::fs`/walkdir 不兼容，需重写 IO 层，成本不成比例 | 已定 | MA1 |
| ADR-5 | 移动布局判定 | Android 强制移动布局（`isAndroid → isMobile=true`），桌面维持 768px 断点 | 平板横屏 ≥768px 会落入鼠标导向的桌面布局，触控不可用；平板双栏是 V1.1+ 的事 | 已定 | MA1 |
| ADR-6 | 移动端凭据存储 | Android Keystore（AES-GCM 包裹）加密后入库，抽象 `SecretStore` trait 与桌面 keyring 对齐 | 现有 XOR 方案密钥与路径绑定，跨设备恢复必失败（审计 P1-08）；Keystore 硬件级保护 | 已定 | MA3 |
| ADR-7 | 移动端同步语义 | 仅手动备份/恢复，恢复后本地来源需重新授权（桌面快照含设备专属路径），不自动同步 | 继承桌面审计 P1-09 结论，防止数据事故 | 已定 | MA3 |
| ADR-8 | 发布渠道 | v1 仅 GitHub Releases 签名 APK 侧载 + 应用内「检查更新」；Play 商店后置 | 侧载无需商店审核/隐私政策/资产；先验证真实使用反馈 | 已定 | MA5 |
| ADR-9 | gen/android 版本管理 | gen/android 已入库（40 文件，含后续 LUMO-CUSTOM 手写段），`@tauri-apps/cli` 锁定 2.11.2 | 手写的 MainActivity/gradle.properties 等在 gen 内，重新生成会丢失；CLI 版本漂移会造成 gen 结构不兼容 | **已生效** | MA0 |
| ADR-10 | cpal/oboe 的 Android 上下文 | MainActivity.onCreate 经 JNI 注入 `ndk_context::initialize_android_context`（Rust 导出 `initLumoAudioContext`） | Tauri 2 的 wry 胶水不初始化 ndk-glue 风格上下文，cpal 依赖它，缺失即 panic；见 MA0 偏差 5 | **已生效**（模拟器验证） | MA0 |
| ADR-11 | Android 构建配套 | ① build.rs 对 android 注入 `-lc++_shared` 链接参数；② 构建 JDK 固定 21（gradle.properties org.gradle.java.home，本机路径） | oboe C++ 依赖缺 libc++_shared DT_NEEDED 会 dlopen 崩溃；JDK 25 版本串无法被 Gradle 8.14 内嵌 Kotlin 解析。⚠️ CI 需剔除 JDK 本机路径 | **已生效** | MA0 |

## 6. 移动端 v1 发布标准（Definition of Done）

全部满足才允许打 `v1.2.0-android` 类标签对外发布：

1. **功能**：本地闭环（MA1）、后台播放与媒体控制（MA2）、WebDAV 流播与缓存（MA3）验收清单全数勾选。
2. **质量**：≥4 台真机（Android 9/12/14/15，含一台低端机）冒烟清单通过；连续 8 小时后台播放抽样不被杀；杀进程重启后播放状态可恢复。
3. **安全**：无凭据明文入库/入日志（继承桌面 P0-01 脱敏）；APK 使用正式 keystore 签名；Manifest 权限逐一在文档中有用途说明。
4. **工程**：Windows 桌面构建与现有测试不回退；`gen/android` 与签名配置（密钥文件除外）入库；CI 在 tag 上自动产出并挂载 Release。
