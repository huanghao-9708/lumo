# Lumo 项目代码审计与执行计划

> 审计日期：2026-08-28  
> 审计基线：`hotfix/20260828`，提交 `8f89da0`（与 `main`、`origin/main` 同指向）  
> 审计范围：Vue/TypeScript 前端、Tauri/Rust 后端、SQLite 数据模型、WebDAV、播放与缓存、跨设备同步、移动端适配、构建发布与现有产品文档  
> 估算假设：1 名熟悉 Vue、Rust、SQLite 与 Tauri 的全栈工程师；不包含视觉重做；工期已在 P80 中加入约 25%～30% 不确定性缓冲。

## 1. 结论先行

Lumo 的功能覆盖已经超过早期 MVP：本地/WebDAV 扫描、曲库浏览、播放、歌词、收藏、歌单、历史、封面、音频缓存、多版本入口、手动数据库同步和移动端响应式界面均已有代码。但当前版本仍不适合直接作为稳定 V1 发布，原因不是“高级功能不够多”，而是发布、数据一致性、安全和自动化验证存在阻断项。

当前总体状态判定为 **红色（Release Blocked）**：

| 维度 | 状态 | 结论 |
|---|---|---|
| 前端生产构建 | 🔴 | `npm run build` 当前失败，安装包无法正常产出 |
| Rust 编译 | 🟠 | 可以编译，但严格 Clippy 和格式检查不通过 |
| 自动化测试 | 🔴 | `cargo test --all-targets` 实际运行 0 个测试；前端无测试脚本 |
| 本地曲库与扫描 | 🔴 | 主链路已实现，但失败扫描、标签变更、来源删除可能造成可见数据异常 |
| 播放体验 | 🟠 | 基础播放与 gapless 已实现；播放模式、统计和媒体状态仍有确定性问题 |
| WebDAV 音乐 | 🟠 | 能扫描/流播/缓存，但 Range 兼容、超时、错误降级、能力探测未闭环 |
| 跨设备同步 | 🔴 | 当前更接近“整库备份/覆盖恢复”，恢复路径存在失败和数据损坏风险，不是合并同步 |
| 安全与隐私 | 🔴 | WebDAV 密码可能被前端 IPC 日志明文输出；凭据加密、CSP、第三方联网策略不达标 |
| 移动端/跨平台 | 🟠 | 响应式 UI 已有，但尚无移动端打包与真机闭环；桌面窗口最小宽度使移动布局不可达 |
| 产品文档 | 🟠 | 多份路线图与真实代码进度、联网行为、版本号和同步实现不一致 |

建议立即冻结 EQ、更多智能歌单、拼音搜索等功能扩张，先完成 P0/P1 稳定化。稳定 V1 的关键路径预计 **P50 为 23 个工程日，P80 为 30 个工程日**；再补齐后续产品模块预计增加 **8～12 个工程日**。

- **已复现**：构建、测试、Clippy、格式化命令的直接结果。
- **确定性静态缺陷**：由当前控制流、SQL 或 Tauri API 语义可以直接推导，仍应通过回归测试固化。
- **待场景验证**：依赖具体 WebDAV 服务端、操作系统、音频格式或历史数据库，需要 mock/真机复现。

## 3. Bug 与风险清单

### 3.1 P0：发布前必须修复

| ID | 问题与证据 | 影响 | 修复与验收 |
|---|---|---|---|
| P0-01 | **WebDAV 密码会进入前端日志。** IPC 包装对全部参数执行 `JSON.stringify` 并写入控制台（`src/utils/tauriInvoke.ts:30-35,85`）；添加来源、保存/浏览同步配置会传入明文密码（`src/api/scanner.ts:8-9`、`src/api/sync.ts:37-39`）。 | 本机日志、远程调试或崩溃截图可能泄露凭据。 | 对命令和字段做默认拒绝式脱敏；生产构建关闭详细 IPC 日志；增加测试断言日志不含 `password/token/credential`。 |
| P0-02 | **前端生产构建失败。** `SidebarRight.vue` 使用类型中不存在的 `source_kind`、`file_ext`、`bits_per_sample`，并导入未使用的 `onMounted`（`src/components/layout/SidebarRight.vue:2,160,162`）；后端字段实际为 `bit_depth`，Rust DTO 已包含其余字段（`src-tauri/src/models.rs:230-246`）。 | 当前无法可靠打包发布。 | 统一 Rust/TS DTO；移除 `any` 与临时字段名；`npm run build` 必须通过。建议后续自动生成 IPC 类型。 |
| P0-03 | **同步恢复路径不安全且所谓“热重载”不会生效。** 下载文件只校验非空（`src-tauri/src/commands/sync.rs:93-97`），随后重命名正在被连接池使用的 DB（`:101-110`）；失败时没有原子回滚；最后调用 `app.manage(DbState { ... })`（`:133`），而 Tauri 2.11 的 `manage` 在同类型状态已注册时返回 `false`，不会覆盖旧状态。 | Windows 上可能无法重命名；恢复失败可令主 DB 路径缺失；即使文件替换成功，命令仍可能使用旧连接池；损坏或错误云端文件可覆盖本地数据。 | P0 阶段先禁用“热恢复”并改为“下载→SQLite `integrity_check`/schema 校验→原子备份→安全退出→下次启动替换”；任一步失败自动回滚。人工恢复按钮增加二次确认与备份路径提示。 |
| P0-04 | **来源不可访问时可能把整库标记为缺失。** 本地遍历静默过滤目录错误；WebDAV `PROPFIND` 失败后直接 `continue`（`src-tauri/src/services/scanner.rs:226-232`），结束时把所有未进入 `scanned_paths` 的记录更新为 `missing`（本地 `:146-181`；WebDAV `:313-343`），仍发出 `scan-complete`。 | 临时断网、权限错误或部分目录失败会让大量曲目消失/不可播，且 UI 显示扫描完成。 | 只有“完整成功遍历”才能提交缺失标记；采用 scan generation/tombstone 两阶段提交；根目录或任一关键目录失败时保留旧可用状态并发 `scan-error`；同一来源禁止并发扫描。 |
| P0-05 | **增量扫描状态恢复错误。** 已标成 `missing` 的文件即使重新出现且 mtime/size 未变，也会被增量逻辑跳过，而批量恢复语句排除了 `missing`（`src-tauri/src/services/scanner.rs:88-106,178-182`）；原 `error` 记录下一次又会被批量改成 `available`。 | 文件恢复后仍不可用；损坏文件可能显示为可用。 | 对“本次确实见到”的路径逐批更新 `last_seen_at/availability`；保留解析错误状态；增加删除→恢复同文件、错误文件复扫测试。 |
| P0-06 | **Track/MediaFile 一致性会被破坏。** 重扫时 UPSERT 把已有 `media_files.track_id` 改挂到新 Track（`src-tauri/src/services/library.rs:200-214`），但不清理旧 Track、收藏/歌单关系和冗余计数；删除来源或主文件失效后也不重选 `tracks.primary_file_id`（字段本身无外键，`src-tauri/src/db.rs:126`；删除逻辑见 `src-tauri/src/commands/scanner.rs:153-178`）。 | 标签修改后出现幽灵计数/歌单断链；多来源歌曲删除主来源后可能从常规查询消失，即使另一版本仍可用。 | 将重索引改为事务内“更新现有实体或安全迁移关联”；来源删除/文件失效后按可用性和优先级重选 primary；加孤儿审计 SQL 与数据库约束/修复迁移。 |
| P0-07 | **默认联网行为违反产品隐私承诺。** 愿景称唯一网络活动是用户配置的 WebDAV（`resources/doc/VISION.md:61`），但切到无歌词歌曲会自动向 LRCLIB 发送歌名/艺人/专辑/时长（`src/stores/player.ts:891-895`、`src-tauri/src/commands/library.rs:205-244`），进入缺封面专辑/艺人会自动访问 iTunes（`src/stores/player.ts:1022,1186`）。 | 未告知的第三方数据请求破坏“零遥测/数据私有”定位，带来隐私和信任风险。 | 默认关闭在线元数据；首次启用时说明数据字段和服务商；设置中可单独开关歌词/封面并支持撤回；更新隐私说明；离线时不发请求。 |

### 3.2 P1：稳定 V1 必须修复

| ID | 问题与证据 | 影响 | 修复与验收 |
|---|---|---|---|
| P1-01 | **“顺序播放”和“列表循环”行为相同。** gapless 预加载和普通切歌都用取模计算下一首（`src/stores/player.ts:1442-1450,1553-1567`）。 | 顺序模式播完最后一首仍回到第一首；单曲队列会无限重复。 | 建立明确状态机：normal 到末尾停止；repeat 才回到开头；repeat-one 重播当前；shuffle 避免可行时立即重复并维护历史。 |
| P1-02 | **gapless 切歌后系统媒体信息未更新。** 静默切换只更新索引/时长（`src/stores/player.ts:1469-1486`），没有调用 `updateMediaSessionMetadata`。 | 系统锁屏/媒体面板仍显示上一首。 | 静默切换时同步媒体元数据、播放状态和文件信息；加 store 单测。 |
| P1-03 | **播放历史记录了错误音源。** SQL 把 `source_kind` 固定为 `local`，并读取 Track 当前 primary，而不是本次实际播放的 media file（`src-tauri/src/repositories/track_repo.rs:77-90`）。 | WebDAV 使用统计、多版本统计、诊断数据错误。 | `record_play` 接收实际 media_file_id，SQL JOIN 获取实际来源；覆盖本地、WebDAV、缓存命中、离线回退、手动切版本测试。 |
| P1-04 | **多版本切换仍是临时实现。** 前端直接修改当前对象的 `primary_file_id` 后重播，未持久化偏好（`src/components/layout/SidebarRight.vue:62-70`）；文件信息查询 `LIMIT 1` 且未按当前 primary 排序（`src-tauri/src/commands/library.rs:278-312`）。 | UI 可能显示与实际播放版本不同，刷新后切换失效。 | 新增 `playback_play_version(track_id, media_file_id)` 或显式选源命令；文件信息按实际播放 ID 返回；是否持久化由产品设置决定。 |
| P1-05 | **WebDAV Range 兼容与错误处理不完整。** Client 无超时（`src-tauri/src/services/webdav.rs:28`）；多处 URL `unwrap` 可因用户/服务端路径触发 panic（`:48-73`、scanner `:287-288`）；Range 请求接受任意 2xx 而不要求/校验 206 与 `Content-Range`（webdav `:278-294`）；`source_capabilities` 表未被使用。 | 不支持 Range 的服务端可能从错误偏移读取，弱网可长期卡住，特殊路径可能崩溃。 | 实现 HEAD/Range/ETag 能力探测；206 与 Content-Range 严格校验，200 时明确降级为完整缓存；设置连接/读取/总超时与取消；所有 URL 操作返回可解释错误。 |
| P1-06 | **离线降级 UI 未闭环。** `uiStore.isOnline` 只被赋值，组件没有消费；`playbackIsCached` API 也没有调用方。`force_local` 找不到本地替代时仍继续尝试 WebDAV。 | 纯云端未缓存曲目离线时仍可能长时间等待；“离线置灰”功能名义上存在、实际上没有。 | 后端提供 `playability` 批量状态；离线未缓存曲目置灰并解释原因；缓存命中/本地替代可播；不要只依赖 `navigator.onLine`。 |
| P1-07 | **缓存管理不完整。** 音频缓存明确没有 LRU（`src-tauri/src/services/cache.rs:52`），虽有查询/清理 API，但前端无调用；设置页只清封面。清封面会删除 artwork 记录与专辑关联（`src-tauri/src/commands/library.rs:368-381`），增量扫描又不会重提取未变化文件。前端封面 LRU 上限估算可达 330MB（`src/utils/artworkCache.ts:15-20`），与愿景中的内存 `<80MB` 冲突。 | 磁盘无限增长；“清理缓存”后内嵌封面可能无法自动恢复；大曲库内存超目标。 | 分离“内存缓存、封面派生缓存、在线图片、音频缓存”；清缓存不删除可恢复性元数据，或建立可重建队列；音频 LRU 加容量/保留策略；UI 显示各类占用。 |
| P1-08 | **凭据保护不达标。** 音乐来源密码使用路径派生 XOR+Base64（`src-tauri/src/commands/scanner.rs:7-38`）；同步密码使用所有设备相同的硬编码 XOR 密钥（`src-tauri/src/services/sync.rs:8-38`）；CSP 为 `null`（`src-tauri/tauri.conf.json:26`）。 | 数据库或同步快照泄露后密码可轻易恢复；WebView 攻击面扩大。 | 密码进入系统 keyring；DB 只保存 opaque reference；同步认证改为设备本地配置，不上传解密材料；设置最小 CSP 与明确 connect-src。 |
| P1-09 | **同步模型与跨设备承诺不一致。** 当前手动上传/下载整个 SQLite；没有自动触发、记录级合并、LWW/冲突检测、ETag 条件写入或 `config.json`。整库还包含设备相关本地路径和机器绑定来源凭据。 | 第二台设备恢复后本地来源路径失效，音乐来源密码无法解密；并发设备可互相覆盖数据。 | 产品上先拆成“备份/恢复”和“跨设备同步”两个能力；V1 可只发布安全备份；真正同步仅同步用户资产表/事件日志，并用 device_id、版本向量/更新时间和 ETag 处理冲突。 |
| P1-10 | **来源删除无确认、扫描无取消/去重。** 桌面设置点击垃圾桶直接执行删除（`src/components/content/Settings.vue:55-56,117`）；后端每次扫描都新建线程，没有 per-source guard。 | 误触立即级联删除索引；重复点击会产生竞态和数据库压力。 | 删除前展示影响范围并二次确认；扫描命令返回 job_id，支持重复请求幂等、取消、错误事件和状态持久化。 |

## 6. 分阶段执行计划

### M0：止血与恢复可发布构建（2～3 工程日）

目标：不再泄露秘密，构建可产出，危险同步能力不会误伤数据。

- 完成 W01、W02。
- 默认关闭详细 IPC AOP 日志；建立字段级脱敏工具。
- 对在线歌词/封面增加总开关，默认关闭，先停止隐式联网。
- 临时禁用“热重载恢复”；保留下载与备份，但要求重启应用完成替换。
- 新增最小 CI：`npm ci`、`npm run build`、`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --all-targets`。

验收：

1. Windows 本地 `npm run build` 通过。
2. 日志抓取中不出现测试密码、Authorization 或完整凭据。
3. 远端不存在/损坏/下载中断时，本地 DB 字节与可查询性保持不变。
4. 未授权在线元数据时，抓包只允许用户主动配置的 WebDAV 请求。

### M1：曲库与扫描数据一致性（5～7 工程日）

目标：任何扫描失败、标签修改、文件恢复、来源删除都不产生幽灵数据或误判缺失。

- 完成 W04、W05。
- 引入 `scan_jobs` 或内存 job registry，单来源同一时刻只允许一个扫描。
- 用 generation 标识或临时表完成“发现→入库→完整成功后标缺失”的两阶段提交。
- 重构 reindex：识别同一路径的旧 track，事务内更新/迁移收藏、歌单、历史和计数。
- 建立 `reselect_primary_file(track_id)`，在失效、删除、恢复、优先级变化后统一调用。
- 添加数据库一致性检查：孤儿 Track、失效 primary、负/漂移计数、无文件歌单项。

验收场景：

1. 本地根目录不存在、无权限、遍历中途失败：旧曲库不变，状态为失败。
2. WebDAV 根/子目录 PROPFIND 超时或 500：旧可用性不变，明确显示失败目录。
3. 删除后恢复同 mtime/size 文件：下一次扫描恢复为 available。
4. 修改歌曲 title/artist/album 标签：只有一个有效 Track，收藏与歌单不丢，统计准确。
5. 同曲多来源移除主来源：自动切换到剩余最佳版本，曲目仍可见可播。

### M2：播放与 WebDAV 可靠性（5～7 工程日）

目标：四种播放模式行为正确，远程服务端差异和弱网不会导致错误播放或无期限等待。

- 完成 W06、W10。
- 将播放队列改为显式状态机，分离“用户队列索引”和 rodio 已预加载队列。
- gapless 静默切换同步媒体信息、歌词/文件信息与历史。
- 记录实际 media_file_id/source_kind。
- 实现 WebDAV capability probe；mock 覆盖 206、忽略 Range 返回 200、无 Content-Length、特殊字符、认证失败、超时、中断重连。
- 离线可播性批量计算；缓存命中/本地替代/不可播三态进入列表 UI。

验收场景：

1. normal 末尾停止，repeat 末尾回首，repeat-one 重播当前，shuffle 可回退且不越界。
2. 本地与 WebDAV gapless 切歌后 UI/MediaSession/歌词/历史全部指向新曲目。
3. 不支持 Range 的服务器明确降级，不从错误 offset 解码。
4. 未缓存的纯 WebDAV 曲目离线点击立即给出原因，不发无期限请求。

### M3：同步与安全模型重构（6～9 工程日）

目标：先交付可靠备份，再决定是否把记录级同步纳入 V1.1。

- 完成 W08、W11。
- `DbState` 改为内部持有可安全替换的 `Arc/RwLock<DbPool>`，或彻底采用“重启后恢复”模型，禁止再次调用 `manage` 覆盖状态。
- 快照上传加入远端临时文件、ETag/If-Match、上传后校验和、原子 rename（服务端支持时）。
- 恢复执行 SQLite header、`integrity_check`、schema version、产品版本和最小表校验；任何失败自动回滚。
- 来源密码、同步密码迁入 OS keyring；同步快照不包含可直接解密的设备凭据。
- 设计同步边界：优先同步 playlists/favorites/history 等用户资产，不同步本地 source path、设备音频缓存和设备偏好。
- 若做多端合并，引入 `device_id`、记录更新时间/删除墓碑、冲突日志和可恢复策略。

验收：

1. 100 次故障注入（下载中断、磁盘满、rename 失败、损坏 DB）均可保留原库并恢复启动。
2. 两设备并发上传不会静默覆盖；至少能检测冲突并要求用户选择。
3. DB/云端快照不含可逆硬编码密钥密码；keyring 缺失时有重新授权流程。
4. 恢复后所有 store 重新加载，播放缓存不会因 media_file_id 重用而播放错误内容。

### M4：缓存、元数据与质量基线（5～7 工程日）

目标：把资源占用和测试从“不可量化”变成可验收。

- 完成 W07、W09，并启动 W12。
- 音频缓存增加默认容量、LRU、固定保留、临时文件回收和设置页管理。
- 封面缓存清理改为可重建；前端内存 LRU 按字节而非条数限额。
- 提取并写入年份、track/disc、genre、bit depth（库支持时）；建立格式样本库和实际支持矩阵。
- 拆分巨型 store/command 文件；前后端类型生成。
- 加单元、集成和最小 Tauri E2E；建立性能基线。

质量指标：

- 核心数据层分支覆盖率 ≥ 80%，扫描/同步/播放状态机 ≥ 90%。
- 1 万首本地曲库增量无变化扫描 P95、首屏查询 P95、切歌延迟有可复现基准。
- 空闲内存、1 万首曲库滚动后内存、封面/音频缓存磁盘上限均有阈值与回归记录。
- 所有 PR 必须通过 build/test/fmt/clippy；禁止新增未解释的 `unwrap`、`any` 和静默 catch。

### M5：产品增强与跨平台（8～12 工程日，稳定 V1 后）

- 智能歌单扩展：最近添加、未播放、流派/年份、可组合规则。
- 拼音/容错搜索：先评估 SQLite FTS5 + 拼音索引，定义万首曲库性能目标。
- M3U/PLS 导入导出与歌单重排。
- 输出设备选择和 ReplayGain；EQ 独立评估，不与稳定化混排。
- macOS/Linux 安装包与媒体键、路径、窗口、音频设备测试。
- Android/iOS 项目初始化、权限与真机验证；补齐移动设置功能后再宣称移动端可用。（2026-08-31 更新：Android 端已展开，详细拆解为 MA0～MA5 六个迭代，见 [`mobile/`](./mobile/) 目录）
