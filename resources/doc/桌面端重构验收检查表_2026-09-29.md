## 2. 人工验收矩阵

### 2.1 尺寸与布局红线

- [ ] 1024×640 / 1200×720 / 1366×768 / 1600×900：无水平整页滚动、无按钮遮挡、无文字覆盖、表头与行对齐
- [ ] 首次启动（清空 `lumo_window_size`）打开为 1200×720；拖小到 1024×640 仍可操作
- [ ] 调整窗口后重启：尺寸被记住；最大化后重启：不记忆最大化（恢复记忆尺寸）
- [ ] 小屏（工作区 < 目标尺寸）启动：窗口完整可见
- [ ] 100% / 125% / 150% 系统缩放各检查一遍
- [ ] 打开右侧 Inspector：内容区宽度不变（浮层覆盖）；关闭入口清楚

### 2.2 侧栏

- [ ] 一级导航、收藏分组、自建歌单行尾均无数字；页面 meta 行统计仍在
- [ ] 超长歌单名省略号截断 + 悬停完整名称；选中态行对齐一致
- [ ] 亮色/暗色主题下选中态、Accent 点正常

### 2.3 统一歌曲列表

- [ ] 全部歌曲 / 收藏 / 最近播放 / 歌单 / 智能歌单 / 专辑详情 / 艺人详情 / 文件夹 / 搜索：表头、列宽、行态、操作入口一致
- [ ] 专辑详情无专辑列；艺人详情无艺术家列；最近播放保留播放时间列
- [ ] 文件夹视图「大小」列钉住显示
- [ ] 双击播放、单击多选切换、收藏心形、艺人/专辑跳转、悬停 Play 图标、正在播放行（橙色竖条 + 均衡器）与重构前行为一致
- [ ] 全部歌曲虚拟列表滚动流畅、分页追加正常、滚动位置记忆正常
- [ ] 播放队列视图（播放列表一级入口）过滤后双击播放的是队列原始位置那首
- [ ] 1200×720 下标准视图可完整阅读 标题/艺术家/专辑/时长/音频；缩窄窗口按 流派→大小→年份→音频→专辑→艺术家→时长 次序收纳
- [ ] 表头「显示列」菜单：详细视图开关 + 年份/流派/大小勾选；偏好保存并在所有列表生效；重启后保留
- [ ] 空列表、无标签（`—`）、超长中英文标题、未知格式展示正确

### 2.4 元数据与补扫

- [ ] 有标签的文件扫描后：年份/流派/音频信息列正确（`MP3 · 320 kbps`、`FLAC · 24bit/96kHz`）
- [ ] 旧曲库（升级前已导入）逐一重新扫描本地与 WebDAV 数据源：各来源完成后年份/流派逐步出现；再次扫描恢复快速增量
- [ ] 补扫不覆盖已有值（已有年份/流派保持）；标签丢失不清空已有流派
- [ ] 多音源歌曲切换首选版本后：音频信息/大小跟随当前首选文件
- [ ] Android：共享 DTO 变更后主要歌曲列表回归（移动端不采用桌面尺寸）

### 2.5 性能对照

- [ ] 对照重构前：首屏时间、列表滚动流畅度、分页耗时、查询条数（列表查询仍是单条 SQL + 一次分页，无逐行 IPC）
- [ ] 30k+ 曲库滚动无明显退化（虚拟列表行高仍为固定 40px）

## 3. 有意保留的差异（非回归）

| 位置 | 差异 | 理由 |
|---|---|---|
| AI 歌单结果卡 | 双行「标题 + 推荐理由」行式、前三名橙色序号 | AI 推荐结果的业务呈现；数据层已统一走 `mapTrackDTO` |
| Inspector 播放队列 | 360px 面板内双行紧凑列表（标题+艺人） | 窄面板变体；MainContent 的队列视图已是标准表 |
| 首页 Top-5 排行卡 | 卡片式、含播放次数 | 首页仪表组件，非曲库列表 |
| 横向滚动 | 用户钉住过多列时可能出现 | 自动列按实际宽度预算收纳；用户显式指定的列保留，超出可用空间时由列表容器横向滚动 |
